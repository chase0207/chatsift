## 1. 真实代码现状(关键调用点)
- admin 单 Vue 应用,**W16 入口按域名分视角**([admin/src/utils/entry.js](admin/src/utils/entry.js)):`mychat.*`→tenant(default `/conversations`)、`admin.*`→platform(default `/dashboard`)、localhost=all 不过滤。`PLATFORM_ROUTES`/`TENANT_ROUTES` 控制各入口可见路由;`filterMenuTree` 过滤菜单。
- 菜单:server `getMenuTree`(menus 表,字段 id/parent_id/name/route/type/permission_code);[MainLayout.vue](admin/src/layouts/MainLayout.vue) 渲染。权限:[permission.js](server/src/middleware/permission.js) `is_super` 放行,否则查 `permission_code ∈ user.permissions`。
- 路由挂载([app.js](server/src/app.js)):`/api/users|roles|menus|platforms|...` + `/api/v1/*`。CRUD 范式 = route(`router.use(auth)` + `perm('x:y')`) → controller → admin api 模块 → Vue view。
- userController([userController.js](server/src/controllers/userController.js)):create/update **只写 role_id**(+ 派生 role 1/9),**未写 user_type/tenant_id**(阶段A 归到 C 的)。
- 配置接口([intentRulesController.js](server/src/controllers/v1/intentRulesController.js):35 等):create/update 用 `tenantId(req)=req.user.tenant_id`,internal=NULL → `tenant_id NOT NULL` 违约 **500**(阶段A 第2点)。
- Dashboard([Dashboard.vue](admin/src/views/Dashboard.vue)):"运行质量监控"块(getAdminStats:关键词命中/转人工/AI调用)= chat_rpa 死指标;基础 stats(users/plugins/messages/devices)来自 [dashboardController.stats](server/src/controllers/dashboardController.js)(★该 controller 还用 `req.user.id` 当 tenant、`data_scope`,是 W19 前遗留)。
- tenants/service_accounts/employee_service_account 表已建(阶段A),**尚无任何 controller/route/UI**。

## 2. 阶段C — admin 租户管理(平台入口)

### C1 租户 CRUD
- **后端**:新增 `tenantController`(list/create/update/remove,普通分页 CRUD,无 scope——租户表是平台级)+ `routes/tenants.js`(`auth` + `perm('tenant:list/create/update/delete')`)+ app.js 挂 `/api/tenants`。
- **menus seed**:加菜单"租户管理"(route `/tenants`,parent=系统设置组 id24 或客服管理组,permission_code `tenant:list`)+ 三按钮权限点(tenant:create/update/delete);给平台管理员(is_super,自动放行)——seed 放 02_w19 续。
- **前端**:新增 `Tenants.vue`(el-table + 新增/编辑 dialog:企业名/联系人/状态/到期/备注)+ `api/tenants.js` + router `/tenants` + entry.js `PLATFORM_ROUTES` 加 `/tenants`。
- ★只平台方可见:`/tenants` 入 PLATFORM_ROUTES;permission 仅配给平台管理员。

### C2 建租户管理员/客服账号(Users.vue + userController 带两层身份)
- **userController**:create 加 `user_type`(默认 external)+ `tenant_id`;update 同。校验:external 必带 tenant_id;internal 则 tenant_id=NULL。role_id 仍写(派生 role 兼容)。
- **Users.vue**:建用户表单加 `user_type`(internal/external 选择,平台入口才显示)+ `tenant_id`(external 时从 /api/tenants 选)。role 下拉已是 role_id(阶段A 改过)。
- **口径**:平台方在 admin 建 internal(平台运营)或为某租户建 external 管理员/客服(选 tenant + role_id)。

### C3 分配客服账号(employee_service_account)
- **后端**:新增 `serviceAccountController`:list service_accounts(按 tenant 过滤,平台方可选租户)、list/assign/unassign employee_service_account(给某租户的客服 employee 绑/解绑账号)。route `/api/service-accounts` + perm。
- **前端**:`Tenants.vue` 内嵌"账号分配"抽屉,或独立 `ServiceAccounts.vue`(选租户 → 列该租户 service_accounts → 给员工勾选分配)。
- **与 B2 关系**:B2 已对客服上报**自动绑定**;C3 是平台方/超管手工调整(补绑/解绑/给非上报客服预绑)。uk_assign 幂等。

### C4 平台方访问租户配置接口 → 403(阶段A 第2点)
- 在 `_shared` 加 `denyInternal(req,res)`(internal → `fail(403,'平台方不可操作租户配置')` 返 true)。
- intentRules/priceTable/llmConfig 的 **create/update/remove/put** 开头调用,internal 直接 403(替代现在 NULL 入库 500)。list/get 不拦(scope 已让 internal 看空)。

### C 验收
- 平台方能建/改租户;能为租户建管理员+客服账号(user_type/tenant_id 正确入库);能分配客服账号(employee_service_account 写入,客服 scope 即生效);平台方调租户配置接口得 403 非 500;`/tenants` 仅平台入口可见、仅平台管理员有权限。

## 3. 阶段D — mychat 首页(租户入口)

### D1 mychat 专属首页
- **后端**:新增 `GET /api/v1/home`(或复用 dashboard route 加 v1 home):返回
  - 主体信息:`tenants WHERE id = req.user.tenant_id`(企业名/联系人/到期)。
  - 看板(按 role_code 分):
    - tenant_admin:企业名 + 本租户员工数(`users WHERE tenant_id=?`)+ 本租户对话/线索/工单总数(走 scope)。
    - agent:登录员工分到账号的对话/线索/工单数(走 scope 的 agent 分支,自动按 employee_service_account)。
  - ★全走 A4 scope helper,隔离天然成立。
- **前端**:新增 `Home.vue`(tenant 视角:主体信息卡 + 插件下载[复用 getPluginUpdate/downloadPluginZip] + 看板卡);router 加 `/home`;entry.js `TENANT_ROUTES` 加 `/home`;`defaultPath('tenant')` `/conversations`→`/home`。
- menus:加"首页"菜单(route `/home`,给租户角色),或前端固定首项。

### D2 移除 Dashboard chat_rpa 死指标(M21)
- [Dashboard.vue](admin/src/views/Dashboard.vue) 移除"运行质量监控"整块(getAdminStats:关键词命中/转人工/AI调用/平均响应时长等死指标)。
- 平台 `/dashboard` 保留基础平台统计(users/plugins/messages/devices)——但 ★[dashboardController.stats](server/src/controllers/dashboardController.js) 用 `req.user.id` 当 tenant + `data_scope` 是 W19 前遗留,顺手对齐到 user_type(internal 平台方看平台级计数,不按 tenant)。
- `api/stats.js` getAdminStats 若仅 Dashboard 用 → 一并废弃。

### D 验收
- mychat 默认进 `/home`;主体信息/插件下载/看板正确;企业级(超管)vs 员工级(客服)按 role_code 区分且数据隔离正确;平台 Dashboard 死指标已清、无残留报错。

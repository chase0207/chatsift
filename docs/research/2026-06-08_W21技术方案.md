# W21 技术方案 — 辅助采集器

> 版本: v1.0.0  
> 日期: 2026-06-08  
> 状态: Draft  
> 输入: `docs/prd/V1.0/W21_design.md` + `docs/research/2026-06-08_W21只读调研与PRD复审.md`  
> 边界: 本文仅为方案;W21 代码实现须等 W20 E1/E2 验收并合回 main 后启动

---

## 1. 总体方案

新增插件运行时模块:

```text
plugin/runtime/assisted-collector.js
```

该模块只负责“低频选择候选会话并调用 adapter.switchSession()”。消息采集、去重、position、上报仍走现有 `legacy-collector + event-collector + event-uploader` 链路。

W21 不新增消息数据契约,不改 W17 position/message_id,不新增发送能力。

## 2. 模块关系

```text
popup auto_switch_session
        |
        v
RpaFeatureFlags + ChatsiftContentGate
        |
        v
AssistedCollector
        |
        +-- AdapterRegistry.resolve(location)
        +-- adapter.detectSessions()
        +-- adapter.switchSession(session)
        +-- adapter.confirmActiveSession(session)
        |
        v
LegacyCollector 现有采集链路自然触发
```

## 3. 状态机

```text
disabled
  -> idle
  -> paused_by_human
  -> scanning
  -> cooldown
  -> blocked_by_w20
```

状态含义:

| 状态 | 含义 |
|---|---|
| disabled | `auto_switch_session=false` 或非目标页面 |
| idle | 开关开启,但未满足无人工操作阈值 |
| paused_by_human | 检测到人工操作,暂停 |
| scanning | 正在处理候选会话 |
| cooldown | 单轮完成后的冷却期 |
| blocked_by_w20 | W20 heartbeat 返回 session block 或采集权不可用 |

## 4. 启动条件

必须同时满足:

- `auto_switch_session=true`
- `collector_v1_enabled=true`
- `ChatsiftContentGate.isAllowed()=true`
- 当前 adapter 为 `douyin/private-message`
- 当前页面能读到 `account_biz_id`
- W20 判定当前员工可采该账号
- 最近人工操作距今超过阈值,默认 15 分钟
- 当前不处于 W20 session block

任一条件不满足,不调用 `switchSession()`。

## 5. W20 采集权检查

优先方案:复用 W20 heartbeat 返回的治理状态。

若 W20 heartbeat 只返回 block/warn,则补一个轻量只读接口:

```text
GET /api/v1/service-accounts/collect-permission
query: platform, platform_page, account_biz_id
return:
{
  allowed: boolean,
  reason: "ok|pending_owner|not_collector|account_disabled|missing_account|unknown",
  lifecycle,
  collector_id,
  collector_kind
}
```

约束:

- 只读接口,不建账号,不改数据。
- 首见建 pending 仍只发生在 events batch 入库路径。
- W21 不绕过 server 端 batch 的最终采集权闸门。

## 6. 候选会话策略

第一版只处理当前可见列表。

候选来源:

```js
sessions = await adapter.detectSessions()
candidates = sessions.filter(s => s.unread_count > 0 && s.dom_ref)
```

排序:

1. `unread_count` 降序。
2. DOM 列表顺序。

限制:

- 单轮最多 5 个。
- 两次切换间隔随机 5-12 秒。
- 单轮结束后冷却 3 分钟。
- 单账号每分钟最多 6 次自动切换。

## 7. 切换流程

单个候选:

```text
1. 再次检查人工互锁和 W20 block 状态
2. adapter.switchSession(session)
3. adapter.confirmActiveSession(session)
4. 等 DOM 稳定 1.5s
5. 再等 3s 给 legacy collector 采集
6. 写本地日志
```

失败处理:

| reason | 处理 |
|---|---|
| auto-switch-disabled | 退出到 disabled |
| no-dom-ref | 跳过候选 |
| switch-timeout | 记录失败,本轮不重试 |
| human-active | 进入 paused_by_human |
| w20-blocked | 进入 blocked_by_w20 |
| non-target-page | 进入 disabled |

## 8. 人工互锁

监听事件:

- `mousemove`
- `mousedown`
- `keydown`
- `wheel`
- `focus`

策略:

- 任一事件更新 `lastHumanActionAt`。
- `scanning` 中检测到人工事件,当前轮立即停止。
- 默认 15 分钟无人工操作后才可重新进入扫描。
- 用户手动关闭开关立即停止并清 timer。

## 9. block / warn

W20 heartbeat 事件:

- `session block`:停止 assisted collector,不再切换会话;legacy collector 是否停采由 W20 E0 逻辑负责。
- `account warn`:记录提醒,但 assisted collector 第一版也应暂停当前轮,避免在已有多实例风险时继续自动切换更多会话。
- 无冲突:允许恢复。

说明:PRD 写 warn 不停采,但 W21 的“自动切换”比采集更有干扰性。建议 warn 不停现有采集,但暂停 assisted collector 当前轮,等冷却后再评估。

## 10. 构建接入

`plugin/build.js` 模块顺序建议:

```text
runtime/instance-identity.js
runtime/event-uploader.js
...
runtime/legacy-collector.js
runtime/assisted-collector.js
```

理由:

- assisted collector 依赖 adapter registry、feature flags、content gate。
- 它不应被 legacy collector 依赖。
- legacy collector 负责采集,assisted collector 只负责切换。

## 11. 不变量

必须保持:

- 不新增发送入口。
- 不调用输入框选择器。
- 不直接调用 `Dom.simulateClick`,只能走 adapter `switchSession()`。
- 不改 `PositionTracker.assign()`。
- 不改 `message_id` 合成规则。
- 不改 server batch 的采集权最终判定。
- 非目标页面 `auto_switch_session` 必须为 false。

## 12. 验收标准

### A. 静态验收

- `rg "sendReply|verifySent|simulateInput|textarea|contenteditable" plugin/runtime/assisted-collector.js` 无发送/输入相关实现。
- `assisted-collector.js` 不直接调用 `Dom.simulateClick`。
- `switchSession()` 关闭开关时返回 `auto-switch-disabled`。
- `npm run build:plugin -- --check` 通过。

### B. 本地模拟验收

- `auto_switch_session=false`:不切换。
- 非目标 URL:不切换。
- 人工事件触发后 1 秒内暂停。
- 候选超过 5 个时只处理 5 个。
- warn 时不调用下一次 `switchSession()`。
- block 时停止调度。

### C. 真机验收

- 抖音私信当前可见 3-5 个未读候选可被低频切换。
- 切换后现有采集链路能入库。
- 人工操作立即暂停。
- 非采集负责人账号不自动切换。
- disabled 账号不自动切换。
- W20 session block 后不自动切换。
- W17 position/message_id/occurred_at 回归通过。

## 13. 分支与实施顺序

W21 代码实施顺序:

1. W20 merge 回 main。
2. 从最新 main 切 `w21-assisted-collector`。
3. 先实现静态闸门和状态机。
4. 再接候选调度。
5. 最后做真机验收。

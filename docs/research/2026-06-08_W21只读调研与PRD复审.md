## 1. 结论

W21 方向成立,但只适合做“显式授权的低频辅助采集”,不适合恢复旧 W18 的“夜间无人值守全自动巡检”。

当前 PRD v1.0.0 的边界合理:

- 默认关闭。
- 用户显式开启。
- 只在目标平台/页面生效。
- 必须服从 W20 采集权和生命周期。
- 人工操作立即暂停。
- 不发送、不回复、不填表。
- 不承诺全量无漏。

建议继续按 W21 推进 tasks/技术方案,但代码实现排在 W20 之后。

## 2. 现有代码能力

### 2.1 自动切换开关已存在

现有 popup 已有“自动切换会话”开关。W21 用户入口定为:

```text
插件面板 -> 客服配置 -> 自动化配置 -> 自动切换会话
```

现有相关实现:

- `plugin/popup/popup.html`: `autoSwitchSession`
- `plugin/popup/popup.js`: 读写 `auto_switch_session`
- `plugin/background.js`: `GET_STATUS` 返回 `autoSwitchSession`,启动平台时写入 `auto_switch_session`

默认值在 `plugin/shared/constants.js`:

```js
auto_switch_session:false
```

结论:W21 不需要新建主开关,应复用现有开关,但需要补充“辅助采集运行态/暂停态/原因提示”。该开关必须默认关闭,关闭后立即停止 assisted collector 调度。

### 2.2 目标页面 gate 已存在

`plugin/shared/content-gate.js` 会读取 `platformDefinitions` 里的平台/页面 URL,并用 `ChatsiftContentGate.isAllowed()` 阻断非目标页面。

`plugin/runtime/feature-flags.js` 已对以下 flag 做了页面 gate:

- `collector_v1_enabled`
- `auto_switch_session`

结论:W21 的目标页面闸门已有基础。后续只需在 assisted collector 启动前再次显式检查,并把失败 reason 记为 `non-target-page`。

注意:该 gate 只判断“是否为已配置采集页面”,并不等于“只允许抖音私信”。W21 第一阶段只做私信,还必须额外要求 `adapter.adapterKey === 'douyin/private-message'`。

### 2.3 抖音私信候选识别已有基础

`plugin/adapters/douyin/private-message.adapter.js` 已实现:

- `detectSessions()`
- unread badge 识别
- `unread_count`
- `selectTriggerSession()`
- `switchSession()`
- `confirmActiveSession()`

候选选择当前是“遇到第一个 `unread_count > 0` 就返回”。W21 需要升级为“当前可见候选列表 + 限量 + 排序 + 节流”,不应继续只取单个 trigger session。

### 2.4 switchSession 已被硬闸保护

三个抖音 adapter 的 `switchSession()` 都先检查:

```js
RpaFeatureFlags.get('auto_switch_session')
```

关闭时返回:

```js
{ ok: false, reason: 'auto-switch-disabled' }
```

结论:现有硬闸正确。W21 不应绕开 adapter 的 `switchSession()` 直接 `simulateClick()`。

### 2.5 缺失能力

当前缺少:

- 独立的辅助采集调度器。
- 人工操作互锁状态机。
- 单轮候选上限和节流。
- W20 采集权前置检查。
- W20 account/block 与辅助采集状态联动。
- 真机验收脚本和观察清单。

### 2.6 P0 技术坑

#### P0-1 legacy 10s debounce 与 3s 缓冲冲突

现有 `legacy-collector` 不是切换后立即采集,而是 MutationObserver 触发 `_scheduleCollect()`,并用 10 秒 debounce。若 W21 切换后只等待 3 秒就切下一个,会反复重置 debounce,导致中间会话静默漏采。

修正方向:

- 推荐:legacy collector 暴露立即采集入口,W21 切换确认后显式触发。
- 备选:单候选停留至少 12 秒,确认 debounce fire 后再切下一个。

#### P0-2 候选 `dom_ref` 跨切换失效

会话切换会导致列表重渲染、未读消失或顺序变化。轮首缓存 5 个 `dom_ref` 后逐个点击,很可能 stale 或误点。

修正方向:

- 轮首只记录稳定候选键。
- 每次切换前重新 `detectSessions()`。
- 按 `raw_id` / `nickname + last_message_text` / `nickname` 重匹配当前 DOM 节点。
- 找不到则跳过。

## 3. PRD 复审

### 3.1 业务真实性

场景真实。当前采集只覆盖打开会话,客服离开或漏点红点会导致诊断数据缺口。W21 可以提升补采覆盖率。

但该能力不是当前 P0。W20 是前置地基,W21 应在 W20 采集权/实例冲突稳定后再写代码。

### 3.2 范围合理性

合理点:

- 只做抖音私信试点。
- 只处理当前可见候选。
- 不做凌晨全量回扫。
- 不做全平台通用。
- 不新增强状态表。

需要保持的硬边界:

- 不深度滚动会话列表。
- 不读取输入框/发送按钮。
- 不主动回复。
- 不把 red-dot 当新消息事实。

### 3.3 技术依赖

W21 依赖 W20:

- `service_accounts.lifecycle`
- `collector_id`
- heartbeat 账号级实例冲突 block(待 W20 验收并 merge 到 main)
- 采集权拒绝原因
- 目标账号 `account_biz_id`

因此 W21 代码实现不得与 W20 E1/E2 并行改同一批插件文件。

拍板:

- Q1:采集权只读接口归 W20 域。W21 不新开 server 采集权接口,只消费 W20 已合并能力。
- Q2:heartbeat 账号级 block 不能写成 main 现成能力,必须标为待 W20 交付并 merge 的依赖。W21 不再依赖 session block 或 warn。

## 4. 调整建议

PRD v1.0.0 可保持为执行依据,但技术方案里需要补三条更明确的约束:

1. W21 assisted collector 不直接调用 `Dom.simulateClick`,只能通过 adapter `switchSession()`。
2. W21 第一版不新增 server 表;如需采集权状态,由 W20 域提供只读能力。
3. W21 真机验收必须单独验证“不影响 W17 position/message_id/occurred_at”。
4. W21 必须解决 legacy 10s debounce 与切换节奏冲突。
5. W21 必须每次切换前重新匹配候选 DOM,不能复用 stale `dom_ref`。

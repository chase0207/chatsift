# DOM 采集新方案调研 — HTML 原文 + LLM 解析(对话区子树)

> 版本: v1.0.0　日期: 2026-06-06　身份: DEV(CC2 调研)　状态: 调研结论,待 Chase/Claude 定是否立项
> 性质: 采集链路范式探索(C 类,若落地触数据契约 + LLM 成本 + 红线隐私),**本文只调研不实现**。
> 动机: Chase 提"当前选择器采集 N 多次不准",设想"直接抓审查元素的 HTML 交给 LLM 识别"。
> 实证样本: 真实抖音私信 outerHTML 一段(life.douyin 来客私信,14 条消息)。

---

## 0. 结论先行
**LLM 从 HTML 解析对话,准确度实证成立**(乱码样本都能 14/14 全对:方向/三种时间形态/客服名两态/卡片/重复连发)。但**不宜替换主采集路径**——与 W17 position 的确定性去重冲突 + 全量 LLM 成本。**推荐落地形态:规则抓取仍做主,把"对话区子树 outerHTML"作 `raw_snapshot` 上报,server 端异步 LLM 解析做"校准对账",持续逼高规则准确度 + 选择器失效时可重放兜底。**

---

## 1. 方案设想
把"逐字段 CSS/XPath 选择器抓取"换成:插件抓对话区 **outerHTML 原文** → 交 LLM(Claude/DeepSeek)解析出结构化(消息/方向/时间条/精确时间/客服昵称)。两层次:
- **A 验证**:手动复制对话 HTML 给 LLM 识别,验证准确度(本次已做)。
- **B 生产**:插件自动抓 `outerHTML` 上报 → server LLM 解析入库。

价值(对应真痛点):① 抗改版(抖音改 class 不再全盘失效)② 不漏字段(HTML 信息全)③ 多平台快(免逐个写选择器)。

## 3. 顺手验证/暴露的 W17·W19 关键点
1. **inbound 有隐藏精确时间(秒)、outbound 客服消息只有分钟级时间条** → 印证 W17"outbound occurred_at=NULL"正确。
2. **客服名两态**: `空月培训教育官方号`(商家账号) vs `空月培训教育官方号-2号客服`(坐席) → 印证 W19 account_biz_id + 坐席模型。**暴露 B 阶段边界**: 第 4、7 条是"官方号"无坐席名(#4 标"抖音 app 端发送")。按 W19 唯一键含 nickname,"官方号"与"官方号-2号客服"会成两个 service_account 行。→ **B2 upsert 需决策**: app 端无坐席名消息,归并到坐席 / 单独成账号 / 用商家账号兜底?(建议补进 W19 阶段B 的 Q)
3. **6 条重复连发**(你好×3 + 多少钱×3,秒级时间)→ 正是 W17 position"靠位置不靠内容"要区分的场景,可作真样本回归。

## 4. token 真相("整段 4000 多"的纠正)
- **整段** outerHTML(含左侧会话列表 + 顶部统计面板 + 客户信息右栏 + 2 个超长 base64 data-uri + 数十个重复 SVG path)粗估 **2 万+字符 / 8–15k token**,大头是 **base64 与 SVG 噪音,不是对话**。
- 真要喂 LLM 的只是**中间对话区子树**(`overflow-y-scroll` 块),且上报前**预清洗**:剥 `elementtiming`/`style`/`<svg>`/base64/`byted-*` 装饰类,只留 `my-4` 结构 + 方向 class + 文本 + 隐藏时间 + 客服名 → **单会话约 1–2k token**。
- **结论**: 成本可行的前提是"**抓对话区子树 + 预清洗**",不是抓整页。

## 5. 与现有体系的冲突/风险
| # | 项 | 说明 |
|---|---|---|
| R1 | **与 W17 非确定性冲突(最深)** | W17 position(锚点窗口逐条确定对齐)是去重 + message_id 幂等地基。LLM 解析非确定:同段 HTML 两次解析逐条边界/顺序可能不同 → position 不幂等 → 去重失效。**不能用 LLM 做去重地基。** |
| R2 | **成本量级跳变** | 现 LLM 仅文本级意图/completeness(规则优先、量小)。把"消息解析"上 LLM 是数量级跃升,撞 tenant_llm_config 配额。 |
| R3 | **采集要精确 vs LLM 要容错** | 采集要时间到秒、不重不漏;LLM 会幻觉/漏条/时间飘。用非确定手段做数据质量地基,方向相反。 |
| R4 | **隐私面扩大** | 抓整块 HTML 上报 + 喂第三方 DeepSeek;HTML 可能含未脱敏 id/token。只读不碰发送红线,但隐私要评估 + 预清洗脱敏。 |
| R5 | **延迟** | LLM 解析延迟影响 W12 准实时提醒。 |

## 6. 推荐落地形态(三选一,我推 X)
- **X(推荐)— LLM 校准对账(离线/异步)**: 规则抓取仍做主(确定、零成本、W17 依赖);把"对话区子树 outerHTML"作 `raw_snapshot` 顺带上报,server 端**异步/抽样**用 LLM 解析,与规则结果**比对**,自动揪规则漏判(方向错/漏条/客服名两态)。不碰实时、不动 W17、不撞配额;选择器失效时这份 HTML 可重放兜底。
- **Y — 失效兜底**: 仅当规则抓不到(选择器失效)才抓 HTML 给 LLM 救场。
- **Z(不推荐)— LLM 替换主路径**: 撞 R1/R2/R3,否决。

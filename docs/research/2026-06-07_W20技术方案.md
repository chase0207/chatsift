## 0. 结论先行
W20 = 在 W19 的 `service_accounts` / `employee_service_account` 上,把现在的**单一"分配"(既采又看)拆成两种权**:
- **采集权(单人)** = `service_accounts.collector_id`(单外键天然表达"同一时间一个负责人")。
- **查看权(多人)** = 复用 `employee_service_account`(语义收敛为"查看权")。
再加 **pending/active/disabled 生命周期**、**采集入库前的采集权校验拦截**、**采集实例冲突检测**、**审计**。
★最大风险:这会**改变 W19 已上线的采集行为**(现在"谁采都入库+无脑自动绑"→ W20"非采集负责人拒绝入库"),需灰度,见 §10/Q5。

## 2. 核心数据模型(★C 类,schema diff 先确认)

### 2.1 service_accounts 扩展(生命周期 + 采集负责人)
```sql
ALTER TABLE service_accounts
  ADD COLUMN lifecycle      VARCHAR(16) NOT NULL DEFAULT 'pending'  -- pending/active/disabled
             COMMENT 'W20 生命周期(替代二态 status 的业务语义)' AFTER status,
  ADD COLUMN first_seen_by  INT DEFAULT NULL COMMENT 'W20 首次发现员工 users.id' AFTER first_seen_at,
  ADD COLUMN collector_id   INT DEFAULT NULL COMMENT 'W20 当前采集负责人(单人=采集权);NULL=无人' AFTER first_seen_by,
  ADD COLUMN collector_kind VARCHAR(8) DEFAULT NULL COMMENT 'temp(pending临时)/formal(active正式)' AFTER collector_id,
  ADD KEY idx_lifecycle (tenant_id, lifecycle),
  ADD CONSTRAINT fk_sa_first_seen FOREIGN KEY (first_seen_by) REFERENCES users(id),
  ADD CONSTRAINT fk_sa_collector  FOREIGN KEY (collector_id)  REFERENCES users(id);
```
- **采集权单人 = 一个外键 collector_id**(不用条件唯一约束;单外键天然"一个账号一个采集人")。
- 旧 `status` 保留兼容(0停用对应 lifecycle=disabled),业务一律读 `lifecycle`。

### 2.2 employee_service_account 语义收敛为"查看权"(多人)
- 结构不变,**COMMENT 改为"员工↔客服账号 查看权(多人)"**。一行 = 一个员工对一个账号的查看权。
- **采集权不再用这张表**(移到 service_accounts.collector_id)。
- scope helper 的 `assignedAccountIds` 含义自然变成"查看权账号集",**代码零改**(查询不变,语义变)。

### 2.3 新增 service_account_audit(审计,PRD §8)
```sql
CREATE TABLE service_account_audit (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id INT NOT NULL,
  operator_user_id INT DEFAULT NULL    COMMENT '操作者(管理员/系统NULL)',
  target_employee_id INT DEFAULT NULL  COMMENT '被操作员工',
  service_account_id INT DEFAULT NULL,
  event_type VARCHAR(40) NOT NULL      COMMENT 'first_seen/temp_grant/confirm/reassign_collector/view_add/view_remove/reject_collect/pending_grab/instance_conflict/old_collector_blocked',
  before_value JSON DEFAULT NULL, after_value JSON DEFAULT NULL,
  device_id VARCHAR(64) DEFAULT NULL, browser_profile_id VARCHAR(64) DEFAULT NULL, tab_id VARCHAR(64) DEFAULT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_tenant_sa (tenant_id, service_account_id), KEY idx_event (tenant_id, event_type, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='W20 客服账号治理审计';
```

### 2.4 新增 collect_instances(采集实例,阶段D)
```sql
CREATE TABLE collect_instances (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id INT NOT NULL, employee_id INT NOT NULL,
  device_id VARCHAR(64) NOT NULL, browser_profile_id VARCHAR(64) DEFAULT NULL, tab_id VARCHAR(64) DEFAULT NULL,
  platform VARCHAR(32), platform_page VARCHAR(64),
  account_biz_id VARCHAR(128) DEFAULT NULL, conversation_id VARCHAR(128) DEFAULT NULL,
  last_seen_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP, status VARCHAR(16) DEFAULT 'active',
  UNIQUE KEY uk_instance (tenant_id, device_id, browser_profile_id, tab_id),
  KEY idx_acct (tenant_id, platform, platform_page, account_biz_id),
  KEY idx_conv (tenant_id, platform, platform_page, account_biz_id, conversation_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='W20 采集实例 heartbeat';
```
- 冲突 key: 账号级 `tenant+platform+page+account_biz_id`;会话级 `+conversation_id`(PRD §6.2)。

## 3. 采集入库:采集权校验拦截(★改 eventsController,替代 autoBindAgent)
现在的 `autoBindAgent`(无脑绑)改为采集权闸门:
```
resolve service_account(biz_id+nick):
  不存在(首见):
    创建 service_account(lifecycle='pending', first_seen_by=本员工,
                         collector_id=本员工, collector_kind='temp')
    写查看权一行(collector 默认可看, PRD §5.3) + 审计 first_seen/temp_grant
    → 允许入库(临时采集权)
  存在:
    lifecycle=disabled → 拒绝入库 + reason='account_disabled'
    本员工 == collector_id → 允许入库
    本员工 != collector_id →
        ★拒绝入库 + reason: pending→'pending_grab' / active→'not_collector'(或 'collector_changed')
        + 审计 reject_collect / old_collector_blocked
```
- **行为变更**: W19"谁采都入" → W20"仅 collector_id 本人可入,他人拒绝"。这是本周期最敏感改动(§10/Q5 灰度)。
- 缺 account_biz_id(resolve 返回 null,现网放行留 sa_id=NULL):W20 仍按现状放行(无账号维度即无采集权可校),还是收紧?→ Q1 关联。

## 4. 查看权过滤(scope helper,基本就位)
- `assignedAccountIds` 已读 employee_service_account = 查看权集,**客服隔离零改**。
- 补一致性:采集权确立(首见 temp / 确认 formal)时**同步写一行查看权**(collector 默认可看)→ scope helper 无需 UNION collector_id,数据自洽。
- 租户超管/internal 分支不变(fail-closed,见 [[chatsift-failclosed-authz]] 口径)。

## 5. admin 客服账号管理扩展(serviceAccountController)
现有 list/employees/assign/unassign 之上加:
| 接口 | 作用 |
|---|---|
| `GET /:id`(或 list 扩字段) | 加 lifecycle / collector(姓名) / collector_kind / first_seen_by / view_count / last_collect_at |
| `POST /:id/confirm` | pending→active;设正式 collector_id(默认=临时采集人,可改)+ 配查看人;collector_kind='formal';审计 confirm |
| `PUT /:id/collector` `{employee_id}` | 采集权重分配;记 old/new collector + 审计 reassign_collector |
| `assign`/`unassign`(复用) | **明确为查看权**增删 |
| `PUT /:id/disable`·`/enable` | lifecycle 切换 |
| `GET /:id/conflicts` | 采集冲突记录(查 audit instance_conflict) |
- 待确认提醒(PRD §7.2): mychat 首页/客服账号页加待办入口(lifecycle=pending 计数 + first_seen_by + 一键确认)。复用 homeController 加 pending 统计。

## 6. 采集实例冲突检测(阶段D)
- **插件**: 生成持久 `device_id`(chrome.storage,首次随机)+ `browser_profile_id` + 每 tab `tab_id`;heartbeat & batch 带上(B1 上报链路已通用透传,加字段即可)。
- **server heartbeat**(现空壳[:192]): upsert collect_instances(last_seen_at);按账号级/会话级 key 查其他活跃实例(last_seen_at 在窗口内):
  - 账号级多实例 → 返回提醒信号。
  - 会话级多实例 → 返回阻止/强提醒信号(Q3)+ 审计 instance_conflict。
- 插件据 heartbeat 返回提示/停采(PRD §7.3 文案)。

## 8. ★关键风险
| # | 风险 | 说明/缓解 |
|---|---|---|
| R1 | **采集行为变更(最敏感)** | W19 现网"谁采都入"→ W20"非 collector 拒绝"。现有员工正在采的账号若 collector_id 未正确初始化,会突然被拒。缓解:迁移时把现有 employee_service_account 的采集者初始化为 collector_id;上线先"只提醒不拒绝"灰度一版,再切硬拒绝(Q5)。 |
| R2 | **数据迁移** | W19 现有 esa 行(autoBind 产生)→ W20 拆:每行 ① 若该账号无 collector 则设 collector_id=employee_id+kind=formal ② 保留行为查看权。lifecycle 现有账号默认 active(已在用)。生产数据量小(刚重采)。 |
| R3 | **pending 数据落点** | 临时采集数据进正式业务表还是待确认库(Q1)。 |
| R4 | **插件实例标识** | device/profile/tab 需插件生成+持久;隐私只读不越界。 |
| R5 | **W17/W19 红线** | 不碰 position/message_id;不重构资产模型。校验拦截只在入库前 gate,不改采集位置逻辑。 |

## 2. 数据模型(完整 schema diff,★C 类先确认)

### 2.1 service_accounts 扩展(生命周期 + 采集负责人)
```sql
ALTER TABLE service_accounts
  ADD COLUMN lifecycle      VARCHAR(16) NOT NULL DEFAULT 'pending'  -- pending/active/disabled
             COMMENT 'W20 生命周期;业务一律读它(旧二态 status 仅兼容)' AFTER status,
  ADD COLUMN first_seen_by  INT DEFAULT NULL COMMENT 'W20 首次发现员工 users.id' AFTER first_seen_at,
  ADD COLUMN collector_id   INT DEFAULT NULL COMMENT 'W20 采集负责人(单人=采集权);NULL=无人' AFTER first_seen_by,
  ADD COLUMN collector_kind VARCHAR(8) DEFAULT NULL COMMENT 'temp(pending临时)/formal(active正式)' AFTER collector_id,
  ADD KEY idx_lifecycle (tenant_id, lifecycle),
  ADD CONSTRAINT fk_sa_first_seen FOREIGN KEY (first_seen_by) REFERENCES users(id),
  ADD CONSTRAINT fk_sa_collector  FOREIGN KEY (collector_id)  REFERENCES users(id);
```
- **采集权单人 = 单外键 collector_id**(不需条件唯一约束)。
- 清库重建场景:fresh DB 直接把这些列并入 02_w19 基线;已有库走 deploy migration。

### 2.2 新建 service_account_view(查看权,多人 — Q2)
```sql
CREATE TABLE service_account_view (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id INT NOT NULL                COMMENT '冗余,便于隔离查询',
  service_account_id INT NOT NULL,
  employee_id INT NOT NULL              COMMENT 'users.id(被授查看权的员工)',
  granted_by INT DEFAULT NULL           COMMENT '授权人;NULL=系统(采集人默认查看权)',
  granted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_view (service_account_id, employee_id),
  KEY idx_emp (employee_id),
  CONSTRAINT fk_sav_tenant   FOREIGN KEY (tenant_id)          REFERENCES tenants(id),
  CONSTRAINT fk_sav_sa       FOREIGN KEY (service_account_id) REFERENCES service_accounts(id),
  CONSTRAINT fk_sav_employee FOREIGN KEY (employee_id)        REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='W20 客服账号查看权(多人)';
```

## 3. 采集入库:采集权硬拒绝闸门(改 eventsController.batch,删 autoBindAgent)
在 `resolveServiceAccountId` 之后、写库之前插入采集权闸门:
```
sa = resolve(biz_id+nick)
sa 为 NULL(缺 account_biz_id / 映射不到):
   维持现状放行,service_account_id 留 NULL(无账号维度,无采集权可校;与 W19 一致)
sa 存在性:
  ① 不存在(首见) → 事务内创建:
       lifecycle='pending', first_seen_by=本员工, collector_id=本员工, collector_kind='temp'
       service_account_view 写一行(本员工, granted_by=NULL 系统默认查看权)
       audit: first_seen + temp_grant
       → 允许入库(临时采集权)
  ② 已存在:
       lifecycle='disabled'         → 403 拒绝, reason='account_disabled'
       本员工 == collector_id        → 允许入库
       本员工 != collector_id        → ★403 直接硬拒绝(Q5,无灰度)
              reason = (lifecycle='pending' ? 'pending_grab' : 'not_collector')
              audit: reject_collect(或 pending=pending_grab / 管理员已改人=old_collector_blocked)
```
- **batch 内 memoize**:同 batch 同账号只解析/校验一次。
- 拒绝粒度:**整批同账号事件一起拒**(返回 rejected 计数 + reason 明细),不部分入库。
- 删除 `autoBindAgent`([eventsController:182])——首见绑定逻辑并入上面 ① 的 collector_id/view 写入。

## 4. 查看权过滤(scope helper 改读 service_account_view)
`_shared.assignedAccountIds`([_shared:57])从读 `employee_service_account` **改读 `service_account_view`**:
```sql
SELECT service_account_id FROM service_account_view WHERE employee_id = ?
```
- 客服分支([_shared:44-49])、internal/tenant_admin/fail-closed 分支**逻辑不变**(见 [[chatsift-failclosed-authz]] 口径)。
- 数据自洽:采集权确立(首见 temp / 确认 formal / 重分配)时**同步维护 view 行**(采集人默认查看权),故 scope helper 不必 UNION collector_id。

## 6. 采集实例冲突检测(阶段D)
- **插件**:生成持久 `device_id`(chrome.storage,首次随机 UUID)+ `browser_profile_id`(profile 维度)+ 每 tab `tab_id`;heartbeat 与 batch 上报均带(上报链路通用透传,加字段即可)。
- **server heartbeat**(现空壳[:192])改为:
  1. upsert `collect_instances`(uk_instance 维度,刷新 last_seen_at + 当前 account_biz_id/conversation_id)。
  2. 查同租户其他**活跃**实例(last_seen_at 在窗口内,如 60s):
     - **会话级** key 命中(同 account_biz_id+conversation_id 另有实例)→ 返回 `{conflict:'session', action:'block'}` + audit instance_conflict。
     - **账号级** key 命中(同 account_biz_id 另有实例,会话不同)→ 返回 `{conflict:'account', action:'warn'}`。
  3. 返回信号给插件 → 插件按 action **停采(block)** 或 **强提醒(warn)**(PRD §7.3 文案)。
- 注:阻止是"采集实例治理"层(停止该 tab 采集上报),非登录会话踢人(PRD §6.1 第一阶段不踢登录)。

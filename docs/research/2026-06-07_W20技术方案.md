## 2. 数据模型(完整 schema diff,★C 类先确认)

### 2.1 service_accounts 扩展(生命周期 + 采集负责人)
```sql
ALTER TABLE service_accounts
  ADD COLUMN lifecycle      VARCHAR(16) NOT NULL DEFAULT 'pending'  -- pending/active/disabled
             COMMENT 'W20 生命周期;★业务判断只看 lifecycle' AFTER status,
  ADD COLUMN first_seen_by  INT DEFAULT NULL COMMENT 'W20 首次发现员工 users.id' AFTER first_seen_at,
  ADD COLUMN collector_id   INT DEFAULT NULL COMMENT 'W20 采集负责人(单人=采集权);NULL=无人' AFTER first_seen_by,
  ADD COLUMN collector_kind VARCHAR(8) DEFAULT NULL COMMENT 'temp(pending临时)/formal(active正式)' AFTER collector_id,
  ADD KEY idx_lifecycle (tenant_id, lifecycle),
  ADD CONSTRAINT fk_sa_first_seen FOREIGN KEY (first_seen_by) REFERENCES users(id),
  ADD CONSTRAINT fk_sa_collector  FOREIGN KEY (collector_id)  REFERENCES users(id);
```
- **采集权单人 = 单外键 collector_id**。
- ★**status 与 lifecycle 双字段**:`status`(旧二态)**暂保留不扩展、不再做业务判断**;W20 一切生命周期判断只读 `lifecycle`(文档明确,避免双字段语义打架)。
- **collector_id 校验**(写入处统一):只能是 `同租户 + user_type='external' + role_code='agent'` 的员工;internal/其他租户/非 agent 一律拒绝(补充#2)。
- ★**lifecycle 默认值='pending'** 对首见合理;现有 service_accounts **无真实用户数据,不做复杂迁移**——保留的旧测试/种子账号默认落 pending,需管理员确认(无用户→可接受)。

### 2.2 新建 service_account_view(查看权,多人 — Q2)
```sql
CREATE TABLE service_account_view (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id INT NOT NULL                COMMENT '冗余,便于隔离查询',
  service_account_id INT NOT NULL,
  employee_id INT NOT NULL              COMMENT 'users.id(被授查看权的员工)',
  granted_by INT DEFAULT NULL           COMMENT '授权人;NULL=系统(采集人默认查看权)',
  granted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_view (service_account_id, employee_id),
  KEY idx_tenant_emp (tenant_id, employee_id),   -- ★客服 scope 高频按(tenant,emp)查查看权(补充#1)
  CONSTRAINT fk_sav_tenant   FOREIGN KEY (tenant_id)          REFERENCES tenants(id),
  CONSTRAINT fk_sav_sa       FOREIGN KEY (service_account_id) REFERENCES service_accounts(id),
  CONSTRAINT fk_sav_employee FOREIGN KEY (employee_id)        REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='W20 客服账号查看权(多人)';
```

### 2.5 新建 collect_instances(采集实例 heartbeat,阶段D — ★唯一键改 NOT NULL 单列)
```sql
CREATE TABLE collect_instances (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id INT NOT NULL, employee_id INT NOT NULL,
  collector_instance_id VARCHAR(64) NOT NULL  COMMENT '★= hash(device_id+browser_profile_id+tab_id),NOT NULL 做唯一键',
  device_id VARCHAR(64) DEFAULT NULL, browser_profile_id VARCHAR(64) DEFAULT NULL, tab_id VARCHAR(64) DEFAULT NULL,
  platform VARCHAR(32), platform_page VARCHAR(64),
  account_biz_id VARCHAR(128) DEFAULT NULL, conversation_id VARCHAR(128) DEFAULT NULL,
  last_seen_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP, status VARCHAR(16) DEFAULT 'active',
  UNIQUE KEY uk_instance (tenant_id, collector_instance_id),   -- ★不含 nullable 字段(避免 NULL-in-uk 多条重复)
  KEY idx_acct (tenant_id, platform, platform_page, account_biz_id),
  KEY idx_conv (tenant_id, platform, platform_page, account_biz_id, conversation_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='W20 采集实例 heartbeat';
```
- 插件侧生成:`device_id`(chrome.storage 持久,首次随机)/ `browser_profile_id`(chrome.storage 持久,可等同 extension install id)/ `tab_id`(sessionStorage 每页签生成)/ **`collector_instance_id = hash(device_id+browser_profile_id+tab_id)`**。

## 3. 采集入库:采集权判定(★event 级 rejected,HTTP 仍 200)
> ★审查反馈#1:**不能整批 403**——EventUploader 批量取≤50 条、跨账号混批,整批 403 会被 requeue 导致合法事件卡死。**HTTP 保持 200,逐 event 判定**;只有 token/internal/服务异常才 401/403/500。

`batch` 现已是 event 级 `{accepted,duplicated,rejected}` + HTTP 200([eventsController:145]),W20 在其中加采集权判定:
```
对每个 event:
  sa = resolveServiceAccount(conn, tenant, event)   // §见下,返回完整状态
  sa == null(缺 account_biz_id/映射不到):
     ★platform_page='private-message'(W20 试点主线)且缺 account_biz_id
        → rejected++, reason='missing_account_biz_id'(否则抖音私信采集权治理被绕过)
     laike/feige 等暂未治理页面 → 维持现状放行,service_account_id 留 NULL
  sa.created == true(本 event 触发首见):
     已在 resolveServiceAccount 内置 pending+collector(temp)+view+audit → accepted 入库
  sa.lifecycle == 'disabled'        → rejected++, reason='account_disabled', audit reject_collect
  本员工 == sa.collector_id          → accepted 入库
  本员工 != sa.collector_id          → ★rejected++(不抛 HTTP)
     reason = (sa.lifecycle=='pending' ? 'pending_grab' : 'not_collector')
     audit = (pending? pending_grab : (collector 被管理员改过? old_collector_blocked : reject_collect))
返回 HTTP 200: { accepted, duplicated, rejected, reject_reasons:[{platform_message_id, reason}] }
插件收到 200 = 该批已处理,不 requeue;按 reject_reasons 提示(PRD §7.3)
```
- internal/token/无 tenant → 仍 403/401([:11] 保留)。服务异常 → 500 + 事务回滚 + 整批 requeue(合理)。
- batch 内 memoize:同账号只 resolve/校验一次。
- 删除 `autoBindAgent`([:182]);首见绑定并入 `resolveServiceAccount`。

### 3.1 resolveServiceAccount(替代 resolveServiceAccountId,★返回完整状态)
> 审查反馈#4:只返回 id 无法区分 首见/pending抢占/active非负责人。改返回对象:
```
resolveServiceAccount(conn, tenant, event) → null | {
  id, lifecycle, collector_id, collector_kind, created  // created=本次是否首次创建
}
逻辑:
  缺 account_biz_id / platform·page 映射不到 → 返回 null(放行/拒绝由 §3 按 page 判:private-message 拒、laike/feige 放行)
  按 uk_account 查 service_accounts:
    命中 → 返回该行 {id,lifecycle,collector_id,collector_kind, created:false}
    未命中(首见) → 事务内:
       INSERT service_accounts(lifecycle='pending', first_seen_by=本员工,
                               collector_id=本员工, collector_kind='temp', first_seen_at=NOW())
       INSERT service_account_view(本员工, granted_by=NULL)   // 采集人默认查看权
       audit: first_seen + temp_grant
       返回 {id, lifecycle:'pending', collector_id:本员工, collector_kind:'temp', created:true}
```
- 并发首见(两实例同时首次):靠 uk_account 唯一键,后到者 INSERT 撞唯一键 → 捕获后改查命中行返回(created:false),避免重复创建。

## 6. 采集实例冲突检测(阶段D)
- **插件**:生成 device_id / browser_profile_id / tab_id / `collector_instance_id`(§2.5);heartbeat 与 batch 均带(上报链路通用透传)。
- **server heartbeat**(现空壳[:192])改:
  1. upsert `collect_instances`(uk_instance=tenant+collector_instance_id,刷新 last_seen_at + 当前 account_biz_id/conversation_id)。
  2. 查同租户其他**活跃**实例(last_seen_at 在窗口内,如 60s,排除自身 collector_instance_id):
     - **会话级**命中(同 account_biz_id+conversation_id)→ `{conflict:'session', action:'block'}` + audit instance_conflict。
     - **账号级**命中(同 account_biz_id,会话不同)→ `{conflict:'account', action:'warn'}`。
  3. 插件按 action **停采(block)** / **强提醒(warn)**(PRD §7.3)。
- 阻止是"采集实例治理"层(停该 tab 采集上报),非登录会话踢人(PRD §6.1 第一阶段不踢登录)。

## 7. ★业务数据展示口径(按 lifecycle,审查反馈#3 修正)

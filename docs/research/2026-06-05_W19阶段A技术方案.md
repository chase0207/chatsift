## 1. 三张新表 DDL(对照现有 schema 风格:InnoDB/utf8mb4_unicode_ci/FK)

```sql
-- 1) tenants 租户主体(admin 手工录入)
CREATE TABLE IF NOT EXISTS tenants (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(128) NOT NULL COMMENT '企业名称',
  contact     VARCHAR(128) DEFAULT NULL COMMENT '联系人/电话',
  status      TINYINT  NOT NULL DEFAULT 1 COMMENT '1=启用 0=停用',
  expire_at   DATETIME DEFAULT NULL COMMENT '到期,NULL=永久',
  remark      VARCHAR(255) DEFAULT NULL,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='租户主体';

-- 2) service_accounts 客服账号(资产原点)
CREATE TABLE IF NOT EXISTS service_accounts (
  id                INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id         INT NOT NULL COMMENT '资产归属租户',
  platform_id       INT NOT NULL COMMENT '全局平台字典',
  page_id           INT DEFAULT NULL COMMENT '全局页面字典(可空,见决策D3)',
  account_biz_id    VARCHAR(128) NOT NULL COMMENT '商家账号稳定ID(=URL accountId)',
  account_nickname  VARCHAR(128) NOT NULL COMMENT '坐席昵称(可改,人工校正)',
  status            TINYINT  NOT NULL DEFAULT 1,
  first_seen_at     DATETIME DEFAULT NULL,
  remark            VARCHAR(255) DEFAULT NULL,
  created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_account (tenant_id, platform_id, page_id, account_biz_id, account_nickname),
  KEY idx_tenant (tenant_id),
  CONSTRAINT fk_sa_tenant   FOREIGN KEY (tenant_id)   REFERENCES tenants(id),
  CONSTRAINT fk_sa_platform FOREIGN KEY (platform_id) REFERENCES platforms(id),
  CONSTRAINT fk_sa_page     FOREIGN KEY (page_id)     REFERENCES platform_pages(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='客服账号(资产原点)';

-- 3) employee_service_account 员工↔账号 多对多分配
CREATE TABLE IF NOT EXISTS employee_service_account (
  id                  INT AUTO_INCREMENT PRIMARY KEY,
  tenant_id           INT NOT NULL COMMENT '冗余,便于隔离查询',
  employee_id         INT NOT NULL COMMENT 'users.id',
  service_account_id  INT NOT NULL,
  assigned_by         INT DEFAULT NULL COMMENT '谁分配;NULL=系统自动',
  assigned_at         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_assign (employee_id, service_account_id),
  KEY idx_sa (service_account_id),
  CONSTRAINT fk_esa_tenant   FOREIGN KEY (tenant_id)          REFERENCES tenants(id),
  CONSTRAINT fk_esa_employee FOREIGN KEY (employee_id)        REFERENCES users(id),
  CONSTRAINT fk_esa_sa       FOREIGN KEY (service_account_id) REFERENCES service_accounts(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='员工↔客服账号分配';
```

★**唯一键含 page_id**:依 design §3.1 + §10.5#1(tasks A1 漏了 page_id,以 design 为准,见决策 D3)。

## 3. 角色清洗 + 统一 role_id(M16,RBAC 分两步)

### 3.1 现状(已查)
- `users`:`role TINYINT(1普通/9管理员)` + `role_id INT FK roles` **双轨(M16)**。
- `roles`:id/name/description/is_super/data_scope(self/dept/all)/status。
- `getUserPermissions` 已是 **role_id-based**(`u.role_id = rp.role_id`)→ 权限本就走 role_id,role(1/9)只剩展示/兜底用。

## 4. tenantId(req) → 统一 scope helper(codex#3,替代裸 tenantId)

### 4.1 现状:tenantId(req) 全部调用点(已查,~31 处 / 8 个 v1 controller)
`tenantId(req)` 定义 = `req.user && req.user.id`([_shared.js:9](server/src/controllers/v1/_shared.js#L9))。调用:
- analyticsController(2)、conversationsController(4)、eventsController(1)、intentRulesController(4)、leadsController(7)、llmConfigController(5)、priceTableController(4)、workordersController(4)。
- 另:`utils/data-scope.js`(self/dept/all)、`dashboardController`(chat_rpa 残留,阶段D 移除)用裸 `req.user.id`。
- columnPref/logs/userController/authController/menuController 的 `req.user.id` 是**用户级**(自己的列偏好/菜单/自查),**非租户业务,scope helper 不动**。

### 4.2 统一 scope helper 设计(禁止 controller 自拼 tenant 条件)
新增 `scope(req, {tenantCol='tenant_id', saCol='service_account_id'})` → 返回 `{sql, params}`,所有业务查询拼接它:
```
内部用户(is_super, tenant_id=NULL):
  - 默认 ' AND 1=0'(★不看任何业务数据,防漏判断误查全部)
  - 仅当显式带 target tenant(req.query/body.tenant_id)→ ' AND tenant_id = ?'
租户管理员(角色=租户管理员):
  - ' AND tenant_id = ?'(req.user.tenant_id),不限 service_account
客服(角色=客服):
  - ' AND tenant_id = ? AND service_account_id IN (分配集)'
  - 分配集 = employee_service_account 查 employee_id=req.user.id;空集→ ' AND 1=0'(无分配看不到)
```
- **阶段A 落地范围**:建 helper + 把 ~31 个 tenantId(req) 调用改走 helper 的 tenant 判定 + 内部用户 NULL 分支。**客服的 service_account_id 分支结构先就位**,但要等阶段B 有归属数据才真正生效(无分配=看不到,是安全默认)。
- eventsController(上报入库)不是"查询隔离",用的是上报者身份定 tenant/account → 单独处理(不套查询 scope)。

### 4.3 tenantId 单点 + 登录/鉴权带 tenant_id
- `_shared.tenantId`:`req.user.id` → `req.user.tenant_id`(供 helper 内部用)。
- 登录 payload + userInfo([authController.js:75-104](server/src/controllers/authController.js#L75))加 `tenant_id`(从 users.tenant_id 查)。
- auth 中间件([auth.js:16-39](server/src/middleware/auth.js#L16))**照现有 is_super/permissions 补全范式**,补 `tenant_id`(旧 token 无 tenant_id 时从 DB 补)。

# W21 Design: 辅助采集器(Assisted Collector)

> 版本: v1.1.0
> 日期: 2026-06-08  
> 状态: Draft  
> 定位: 用户显式授权的低频辅助采集,不再沿用 W18 AutoScanner 编号与方案  
> 范围: 先做抖音私信单页面试点,不做全平台通用巡检

## 1. 背景

chatsift 当前采集链路只采集客服原生页面中当前打开会话的消息。客服在岗时,人工点开会话即可自然触发采集;客服离开座位或未及时查看红点会话时,未打开的会话可能漏采,导致第二天诊断、线索、工单和漏斗数据不完整。

旧 W18 AutoScanner 试图用“夜间无人值守自动点开红点会话 + 滚动 + 兜底回扫”解决该问题。该方向有真实业务痛点,但方案过重,且触碰 chatsift “只读诊断 / Observe First”的默认边界。W21 不继承 W18 的夜间全自动巡检方案,改为更保守的“辅助采集器”。

## 2. 目标

W21 的目标是:在用户明确开启的前提下,插件低频自动切换当前可见的未读候选会话,让现有采集链路有机会补采离岗或漏看的会话。

核心口径:

- 默认关闭。
- 用户显式开启。
- 仅目标平台/目标页面生效。
- 仅有采集权的客服账号生效。
- 检测到人工操作立即暂停。
- 不发送、不回复、不填表。
- 不承诺全量无漏,只提升补采覆盖率。

## 3. 非目标

W21 不做以下内容:

- 不做凌晨 02:00 全量回扫。
- 不做跨平台通用巡检框架。
- 不做深度翻页扫描全部会话。
- 不做复杂 `scan_status = scanned/partial/failed` 状态机。
- 不基于红点直接认定新消息。
- 不接入任何发送、回复、输入框操作。
- 不绕过 W20 采集权治理。

## 4. 真实场景

### 4.1 主要场景

客服打开抖音私信页面并登录 chatsift 插件后,手动开启“自动切换会话”。当客服离开座位一段时间,页面上出现若干未读候选会话。插件在确认当前页面、账号、采集权和人工互锁条件都满足后,低频点开候选会话,让原有 DOM 采集链路采到消息。

### 4.2 次要场景

客服在岗但临时忙碌,开启辅助采集后,插件可帮助轮询少量未读会话。只要检测到鼠标、键盘或页面交互,插件立即暂停,避免抢操作。

### 4.3 不成立场景

电脑休眠、浏览器后台被系统强节流、抖音登录态失效、页面不在目标 URL、当前员工没有采集权时,W21 不尝试强行补采,只记录状态或提醒用户。

## 5. 产品方案

### 5.1 开关

沿用插件现有“自动切换会话”开关,默认关闭。

开启时必须展示清晰提示:

> 开启后插件会自动切换当前客服页面会话,可能影响人工操作。

关闭时立即停止所有自动切换动作。

### 5.2 目标页面闸门

插件只在“平台管理”中已配置的平台/页面 URL 上生效。

第一阶段仅允许:

- 平台:抖音
- 页面:抖音私信

非目标页面返回 `auto-switch-disabled: non-target-page`。

### 5.3 采集权闸门

W21 必须接入 W20 的账号治理口径:

- 当前客服账号无 `account_biz_id`:不自动切换。
- 当前员工不是该客服账号采集负责人:不自动切换,只提醒“当前账号采集权不属于你”。
- `lifecycle = disabled`:不自动切换。
- `lifecycle = pending/active` 且当前员工拥有采集权:允许进入候选处理。

### 5.4 人工互锁

检测以下任一事件后,立即暂停自动切换:

- 鼠标移动
- 鼠标点击
- 键盘输入
- 页面重新获得焦点且距离上次人工事件不足阈值

默认恢复条件:连续 15 分钟无人工操作,且总开关仍开启。

### 5.5 候选会话

候选会话仅来自当前可见会话列表,第一版不主动滚动会话列表加载更多。

候选信号:

- `unread_count > 0`
- 或 adapter 可识别的红点/未读标识

红点只代表“候选”,不代表新消息。是否有新消息仍由现有采集、去重和分析链路判定。

### 5.6 处理策略

单轮最多处理 5 个候选会话。

处理顺序:

1. 优先未读数更高的会话。
2. 同等未读数时,按页面列表顺序从上到下。

每个候选会话:

1. 每次切换前重新 `detectSessions()`。
2. 用稳定候选键重新匹配目标会话,不复用上一轮缓存的 `dom_ref`。
3. 调用 adapter `switchSession(session)`。
4. 等待活动会话确认。
5. 触发或等待现有采集链路完成。
6. 进入下一个候选。

采集完成策略二选一,写代码前必须定死:

- 推荐:切换后显式调用 legacy collector 的立即采集入口,例如 `collectNow()`。
- 备选:每个候选停留至少 12 秒,覆盖 legacy collector 当前 10 秒 debounce 窗口,确认采集 fire 后才切下一个。

节流:

- 两次切换间隔不得低于 12 秒,并叠加随机抖动。
- 单轮结束后至少等待 3 分钟再进入下一轮。
- 单账号每分钟自动切换不超过 6 次。

说明:现有 legacy collector 通过 MutationObserver 触发 `_scheduleCollect()`,且 debounce 为 10 秒。如果 W21 切换后只等 3 秒就切下一个,会反复重置 debounce,导致被切会话不入库。

### 5.7 block / warn 行为

若 W20 实例冲突 heartbeat 返回:

- `block`:停止自动切换和当前 tab 采集,展示强提醒。
- `warn`:展示提醒,但不停止采集和自动切换。
- 无冲突:保持当前状态。

## 6. 技术落点

### 6.1 插件侧

复用现有能力:

- `plugin/shared/dom-utils.js` 的 `simulateClick`
- 各抖音 adapter 的 `switchSession`
- `auto_switch_session` feature flag
- popup 中“自动切换会话”开关

新增或补齐:

- `runtime/assisted-collector.js`
- 目标页面判定
- W20 采集权状态查询或随 heartbeat/context 返回
- 人工互锁状态机
- 低频候选调度器
- block/warn 展示与暂停策略

### 6.2 Server 侧

原则上不新增核心业务表。

可复用:

- W20 `service_accounts.lifecycle`
- W20 `collector_id`
- W20 `collect_instances`
- W20 heartbeat 冲突检测(block/warn;待 W20 Phase D/E 验收并合回 main 后作为 W21 依赖)

采集权只读能力归属 W20 域。若 W21 需要 `collect-permission` 只读接口,由 W20 收口阶段提供接口契约和实现,W21 只消费,不在 W21 分支新开 server 采集权接口。

如需记录运行日志,优先走现有插件日志或运行质量日志,不新增强状态表。

### 6.3 Adapter 侧

第一阶段只改抖音私信 adapter:

- 明确 unread/red-dot 候选识别。
- 确认 `switchSession` 在 `auto_switch_session=false` 时硬拒绝。
- 切换后必须确认 active session。
- 切换失败要返回结构化 reason。

## 7. 验收标准

### 7.1 安全边界

- 默认关闭时,插件绝不自动切换会话。
- 非目标平台/页面,插件绝不自动切换会话。
- 无采集权账号,插件绝不自动切换会话。
- `disabled` 账号,插件绝不自动切换会话。
- 后台和插件都没有发送/回复入口。

### 7.2 人工互锁

- 人工鼠标/键盘操作后 1 秒内暂停自动切换。
- 暂停期间不会继续点开候选会话。
- 用户关闭开关后立即停止。

### 7.3 采集效果

- 抖音私信页面开启后,可自动切换 3-5 个当前可见未读候选会话。
- 被切换会话触发现有采集链路,消息可入库。
- 不影响 W17 `position/message_id/occurred_at` 规则。
- 不绕过 W20 采集权拦截。

### 7.4 节流

- 单轮最多 5 个候选。
- 单账号每分钟自动切换不超过 6 次。
- 单轮结束后至少等待 3 分钟。

## 8. 风险与控制

| 风险 | 控制 |
|---|---|
| 干扰人工客服操作 | 默认关闭 + 显式提示 + 人工互锁 |
| 平台风控 | 低频、限量、随机延迟、不做深度翻页 |
| 错误页面误触发 | 目标页面闸门 |
| 非负责人采集 | W20 采集权闸门 |
| 页面 DOM 变化 | 仅抖音私信试点,adapter 明确 reason |
| 误以为全量无漏 | 产品文案明确“辅助补采,不保证全量” |

## 9. 分阶段计划

### 阶段 A:方案与闸门

- 确认目标页面 URL 来源。
- 确认 W20 采集权状态获取方式。
- 梳理当前 `switchSession` 的三个抖音 adapter 行为。

### 阶段 B:本地插件 MVP

- 实现 `assisted-collector` 状态机。
- 接入开关、目标页、采集权、人工互锁。
- 只处理当前可见候选。

### 阶段 C:抖音私信真机验收

- 单账号单浏览器。
- 单账号多 tab。
- 两员工账号采集权冲突。
- 人工介入暂停。

### 阶段 D:是否扩展

只有当抖音私信连续稳定通过后,再评估:

- 抖音来客其他页面。
- 飞鸽页面。
- 其他平台逐个 adapter 配置。

## 10. 与 W18 的关系

W18 `docs/prd/V1.0/W18_自动巡检器.md` 保留为历史方案,不再作为执行依据。

W21 是新的执行编号和新方案:

- 从“夜间全自动巡检”改为“显式授权辅助采集”。
- 从“全量红点回扫”改为“当前可见候选低频切换”。
- 从“复杂 scan_status 状态机”改为“复用现有采集链路和 W20 治理”。
- 从“尽量无人值守”改为“用户可控、可暂停、可解释”。

# W22 PRD: 工单中心优化

> 本文只定义产品范围与验收口径,不直接指导代码实现。后续由 CC1 基于本文输出技术方案。
> W22 不改 schema、不改分析引擎、不改工单类型枚举、不做发送/回复。

## 1. 背景与目标

### 1.1 背景

现有工单中心更像“工单技术列表”,主要展示标题、类型、优先级、状态、SLA 等工单自身字段。运营人员进入页面后,很难直接判断:

- 这个工单对应哪个客户。
- 客户在 IM 里的昵称是什么。
- 系统从消息中提取到的客户姓名是什么。
- 当前工单为什么被生成。
- 应该回到哪段对话继续处理。

同时,“类型”字段已经可以由工单类型 tab 承担,“标题”字段多为类型化文本,对实际处理价值有限。继续把它们放在列表主区,会挤占客户身份、关键词和处理状态等更重要的信息。

W22 的目标是把工单中心从“工单属性列表”调整为“租户员工处理客户工单的工作台”,让员工先看清客户、关键词、状态和对话记录。

### 1.2 目标

1. 用 tab 承担工单类型分流,替代列表和搜索区域里的“类型”字段。
2. 去掉“标题”字段,释放列表空间。
3. 增加并明确“IM昵称 / 客户姓名 / 关键词 / 状态”的展示与交互规则。
4. 状态在列表内直接下拉修改,失焦即保存,不再依赖“查看/处理”弹窗。
5. 新增“查看记录”入口,通过右侧抽屉查看对话内容与客户全貌。
6. 保持 chatsift 只读诊断定位,不引入发送、回复、输入、自动处理能力。

---

## 2. 范围

W22 只改租户管理后台的工单中心页面。

包含:

- 工单中心列表字段调整。
- 工单中心搜索区域调整。
- 工单类型 tab 分类与数量统计。
- 工单状态下拉修改交互。
- “查看记录”蓝色文字按钮。
- 右侧抽屉展示对话内容与客户全貌。
- 与工单中心相关的只读展示接口适配,以前端实现和现有接口能力为优先。

不包含:

- 平台管理后台。
- 会话中心、线索中心、运营分析、控制台等其它页面的整体重构。
- 工单生成逻辑、分析逻辑、采集逻辑、权限体系的重构。

---

## 3. 非目标

W22 明确不做以下事项:

- 不改数据库 schema。
- 不新增、删除或重命名工单类型枚举。
- 不改分析引擎。
- 不改工单生成规则。
- 不改线索引擎。
- 不改采集插件。
- 不新增发送、回复、输入框、自动回复、自动处理能力。
- 不做关键词高亮。
- 不做跨页面的大型客户中心重构。
- 不做新的工单详情独立页面。

工单类型枚举仍沿用现有系统值。前端展示文案可以调整,例如 `pricing` 展示为“询价”,但底层枚举不变。

## 4. 字段定义

### 4.1 列表字段

| 字段 | 展示规则 | 说明 |
|---|---|---|
| IM昵称 | 展示从会话中采集到的客户 IM 昵称 | 用于识别原生平台里的客户身份。它不是客户真实姓名。 |
| 客户姓名 | 展示原“客户”字段,即从消息中提取到的客户姓名 | 与 IM昵称区分。若未提取到姓名,展示 `-`。 |
| 关键词 | 展示采集到的、与当前工单有关的关键信息,支持多条 | 最多展示 2 行,超出后以省略号处理。第一版不做高亮。 |
| 状态 | 支持下拉修改 | 失焦即保存,保存成功提示“状态修改成功”。 |
| 优先级 | 保留现有优先级展示 | 若空间不足,技术方案可评估弱化展示,但不改变字段含义。 |
| SLA/创建时间 | 保留必要的处理辅助信息 | 展示形态由技术方案按现有页面约束确定。 |
| 操作 | 只保留“查看记录” | 蓝色文字按钮,点击打开右侧抽屉。 |

### 4.2 去掉字段

| 字段 | 调整 |
|---|---|
| 类型 | 列表去掉,搜索区域也去掉。类型筛选由 tab 承担。 |
| 标题 | 列表去掉。 |
| 查看/处理 | 操作区去掉。状态修改已由“状态”下拉替代。 |

### 4.3 字段口径

#### IM昵称

IM昵称指从平台会话中采集到的客户昵称,用于帮助员工在原生客服页面中定位客户。它不等同于客户姓名。

#### 客户姓名

客户姓名指系统从消息内容中提取到的客户真实姓名或预约姓名。原页面中的“客户”字段在 W22 中统一命名为“客户姓名”。

#### 关键词

关键词指与当前工单处理有关的关键信息。它可以来自当前工单 payload、关联会话、关联线索或消息内容中的关键字段,但 W22 不要求新增分析引擎或新建字段。

展示要求:

- 支持多条关键词。
- 最多展示 2 行。
- 超出 2 行后省略。
- 第一版不做关键词高亮。
- 若无关键词,展示 `-`。

#### 状态

状态使用现有工单状态值,不新增枚举。前端展示文案可按现有产品语言映射,但不得改变底层状态含义。

状态下拉是 W22 的主要处理入口。员工在列表中直接修改状态即可完成处理动作。

## 5. Tab 分类

### 5.1 Tab 列表

工单中心按工单类型做 tab 分类。

Tab 顺序:

1. 全部
2. 预约
3. 咨询
4. 询价
5. 投诉

其中“询价”对应原“报价”展示文案,底层仍使用现有工单类型枚举。

### 5.2 数字统计

每个 tab 都展示数量统计。

示例:

```text
全部(239)  预约(80)  咨询(63)  询价(54)  投诉(42)
```

统计口径:

- 全部:当前租户、当前权限范围内的全部工单数量。
- 预约:当前租户、当前权限范围内,类型为预约的工单数量。
- 咨询:当前租户、当前权限范围内,类型为咨询的工单数量。
- 询价:当前租户、当前权限范围内,类型为报价/询价的工单数量。
- 投诉:当前租户、当前权限范围内,类型为投诉的工单数量。

Tab 数字统计应与当前用户可见数据范围一致,不能显示用户无权查看的数据。

### 5.3 Tab 与搜索关系

Tab 是类型范围,搜索是范围内过滤。

当用户选中某个 tab 后,搜索条件只在该 tab 对应的工单范围内生效。

示例:

- 当前 tab = 预约,搜索 IM昵称“张三”。
- 结果 = 预约工单中 IM昵称匹配“张三”的记录。
- 不应返回咨询、询价、投诉工单。

## 6. 搜索规则

### 6.1 搜索区域字段

搜索区域去掉“类型”字段。

保留或新增的搜索条件以实际技术方案为准,但必须满足:

- 搜索条件叠加在当前 tab 下。
- 不允许搜索条件绕过 tab 类型范围。
- 搜索结果与列表字段口径一致。

建议搜索条件:

| 条件 | 口径 |
|---|---|
| IM昵称 | 按会话采集昵称搜索 |
| 客户姓名 | 按提取到的客户姓名搜索 |
| 关键词 | 按当前工单相关关键词或消息内容搜索 |
| 状态 | 按工单状态搜索 |

### 6.2 叠加规则

搜索条件之间采用 AND 关系。

示例:

```text
当前 tab = 投诉
状态 = 待处理
关键词 = 退款
```

结果应为:

```text
投诉 tab 下,状态为待处理,且关键词/相关内容命中“退款”的工单
```

### 6.3 重置规则

重置搜索条件时:

- 清空搜索区域字段。
- 保留当前 tab。
- 列表回到当前 tab 的默认结果。

## 7. 状态修改规则

### 7.1 修改入口

列表“状态”列展示为下拉控件。

用户点击下拉并选择新状态后,该行进入待保存状态。

### 7.2 保存时机

状态修改采用“失焦即保存”。

失焦包括:

- 用户选择状态后点击页面其它区域。
- 用户切换到其它控件。
- 用户离开当前下拉控件焦点。

技术方案可根据前端组件行为确定最稳定的触发点,但产品体验必须表现为:用户无需点击额外“确认”按钮。

### 7.3 防重复提交

同一行状态保存中时:

- 禁止重复提交同一状态修改。
- 该行状态控件应进入保存中或禁用态。
- 保存完成前,不应发起第二次相同请求。

如果用户连续选择多个不同状态,技术方案需保证最终状态可预期,不得出现旧请求覆盖新选择的情况。

### 7.4 成功提示

保存成功后展示提示:

```text
状态修改成功
```

### 7.5 失败处理

保存失败时:

- 保持或回滚到服务端确认的状态。
- 给出失败提示。
- 不静默吞掉错误。

失败处理不新增复杂流程,以避免误导用户认为状态已保存。

## 8. 抽屉规则

### 8.1 入口

操作列新增蓝色文字按钮:

```text
查看记录
```

点击后,从右向左打开抽屉页。

原“查看/处理”入口去掉。工单处理通过列表状态下拉完成。

### 8.2 抽屉结构

抽屉页分两列,复用“聚合消息”三栏中的右侧两栏思路:

1. 第一栏:不展示。
2. 第二栏:对话内容。
3. 第三栏:客户全貌。

W22 抽屉只展示第二栏和第三栏。

### 8.3 第二栏:对话内容

展示该工单关联会话的对话内容。

打开抽屉时,对话内容应尽量定位到“关键词”所在位置,帮助员工快速看到工单触发上下文。

第一版不做关键词高亮。

如果无法准确定位关键词位置,允许定位到关联工单附近的消息区段或会话最新消息,但技术方案需说明降级规则。

### 8.4 第三栏:客户全貌

展示与当前工单客户相关的全貌信息,用于辅助处理。

建议包含:

- IM昵称。
- 客户姓名。
- 联系方式。
- 城市。
- 用车/预约相关字段。
- 当前线索状态或意向等级。
- 关联会话/工单摘要。

具体字段以现有数据可用性为准,不得为 W22 新增 schema。

### 8.5 抽屉非目标

第一版抽屉不做:

- 关键词高亮。
- 发送/回复。
- 输入框。
- 工单状态编辑。
- 客户资料编辑。
- 线索状态编辑。
- 新建工单。

## 9. 验收标准

### 9.1 列表字段

- 工单中心列表不再展示“类型”字段。
- 工单中心列表不再展示“标题”字段。
- 搜索区域不再展示“类型”搜索项。
- 列表展示“IM昵称”。
- 列表展示“客户姓名”。
- 列表展示“关键词”。
- 关键词最多展示 2 行,超出后省略。
- 列表展示“状态”下拉控件。
- 操作列只保留“查看记录”,不再展示“查看/处理”。

### 9.2 Tab 分类

- Tab 顺序为:全部、预约、咨询、询价、投诉。
- 每个 tab 展示数量统计。
- “询价”展示文案替代原“报价”文案。
- 切换 tab 后,列表仅展示对应类型范围内的工单。
- 全部 tab 展示当前可见范围内全部工单。

### 9.3 搜索

- 搜索条件仅在当前 tab 下生效。
- 多个搜索条件为叠加过滤。
- 重置搜索后保留当前 tab。
- 去掉类型搜索后,用户仍可通过 tab 完成类型切换。

### 9.4 状态修改

- 状态字段可通过下拉修改。
- 修改后失焦即保存。
- 保存成功后提示“状态修改成功”。
- 保存中防止重复提交。
- 保存失败时不静默失败,需提示用户并保持服务端可信状态。

### 9.5 查看记录抽屉

- 点击“查看记录”后,右侧抽屉打开。
- 抽屉只展示两列:对话内容、客户全貌。
- 抽屉不展示聚合消息的第一栏。
- 对话内容尽量定位到关键词所在位置。
- 第一版不做关键词高亮。
- 抽屉内不出现发送/回复/输入能力。

### 9.6 边界验收

- 不改 schema。
- 不改分析引擎。
- 不改工单类型枚举。
- 不新增发送/回复能力。
- 不影响会话中心、线索中心、运营分析等其它页面的既有入口。

## 10. 风险与边界

### 10.1 数据可用性风险

IM昵称、客户姓名、关键词、客户全貌依赖现有采集、分析和关联数据。若历史数据缺字段,页面应展示 `-` 或降级信息,不应为了补齐展示而改 schema 或改引擎。

### 10.2 关键词口径风险

“关键词”是运营视角字段,但当前系统不一定存在独立的关键词字段。W22 产品口径要求展示“与当前工单有关的关键信息”,技术方案需基于现有数据源设计提取/拼装方式。

如果现有数据不足以稳定生成关键词,第一版允许采用保守降级:

- 优先展示工单 payload 中的关键字段。
- 其次展示关联线索/会话中的关键字段。
- 再其次展示 `-`。

不得为追求关键词展示而修改分析引擎。

### 10.3 状态失焦保存风险

失焦保存比确认按钮更轻,但更容易出现重复请求、快速切换覆盖和失败状态不清的问题。技术方案必须明确防重复提交与失败回滚策略。

### 10.4 Tab 统计风险

Tab 数字必须与当前租户、当前权限范围一致。不得为了显示总数而暴露用户无权查看的数据。

### 10.5 抽屉定位风险

“定位到关键词位置”依赖关键词和消息之间的可匹配关系。若无法准确定位,允许降级到关联消息区段或会话最新位置,但必须保证抽屉仍可读、不卡死、不误导用户。

### 10.6 只读边界

查看记录抽屉只用于查看对话内容与客户全貌。任何发送、回复、输入、自动处理、自动点开原生平台页面的能力都不属于 W22。

### 10.7 变更分类

W22 PRD 本身是产品文档。后续技术方案若涉及以下内容,必须升级为 B/C 类审查:

- schema 变更。
- 工单类型枚举变更。
- 分析引擎变更。
- 数据权限契约变更。
- 跨页面客户中心重构。
- 发送/回复/主动操作页面能力。

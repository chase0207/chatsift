# W12.6 诊断报告 — 消息时间/顺序错乱

## 结论

这次不改代码、不改数据库。

当前证据显示,抖音私信采集的 `occurred_at` 来自 `private-message.adapter.js` 对 DOM 时间文本的解析。该解析只稳定支持完整格式 `YYYY-MM-DD HH:mm[:ss]`,不支持 `昨天`、`今天`、`刚刚`、`30秒` 等相对时间。解析失败时会 fallback 到采集当刻 `new Date()`。

`chase` 会话里同一个上传批次内同时出现:

- 部分消息 `occurred_at` 约等于 `uploaded_at`,说明走了 fallback。
- `儿童节快乐` 的 `occurred_at=2026-05-31 22:46:00`,但 `uploaded_at=2026-06-01 07:23:38`,说明这条不是 fallback,而是从 DOM 解析/继承到了一个旧的完整时间。

因此时间错乱不是后台展示排序造成的。后台按 `occurred_at ASC, id ASC` 排序,它只是把采集侧写入的错误时间忠实展示出来。

### 抖音私信 getMessages

`plugin/adapters/douyin/private-message.adapter.js`:

```js
async function getMessages(session) {
  void session
  if (/life\.douyin\.com\/cs\/web\/clue_private_message/.test(location.href || '')) {
    var items = Dom.queryAll('div[class*="my-4"]').filter(Dom.isVisible)
    var currentDate = ''
    var list = []
    items.forEach(function (el) {
      var text = _extractMessageText(el)
      if (!text) {
        var systemText = Dom.getText(el)
        if (/^\d{4}-\d{2}-\d{2}\s+\d{2}:\d{2}/.test(systemText)) currentDate = systemText
        return
      }
      var timeText = _extractMessageTime(el) || currentDate
      var direction = _isOutbound(el) ? 'outbound' : 'inbound'
      list.push({
        direction: direction,
        owner: direction === 'outbound' ? 'self' : 'user',
        message_type: 'user_text',
        type: 'text',
        content: text,
        timestamp: _normalizeOccurredAt(timeText),
        raw_payload: { selector: 'life-message-item', rect: Dom.readRect(el) },
      })
    })
    return list
  }
}
```

要点:

- life.douyin 私信页用 `div[class*="my-4"]` 作为消息/时间分隔候选。
- 无文本气泡时,如果整行文本匹配完整时间 `YYYY-MM-DD HH:mm`,就写入 `currentDate`。
- 有文本气泡时,优先取消息内时间 `_extractMessageTime(el)`,否则继承 `currentDate`。
- `currentDate` 只接收完整绝对时间,不处理相对时间。

### 时间节点提取

```js
function _extractMessageTime(el) {
  return Dom.getTextByXpath(el, './/span[contains(@class,"text-xs")]') ||
    Dom.getTextByXpath(el, './/p[contains(@class,"text")]//span')
}
```

风险:

- XPath 是在整条 `my-4` 内找第一个 `span.text-xs`,不是更精确的“消息时间”节点。
- 如果 DOM 结构里有其他 `text-xs` span,可能误取。
- 如果单条消息没有独立时间,会继承 `currentDate`。

### 时间标准化

```js
function _normalizeOccurredAt(value) {
  if (!value) return new Date().toISOString()
  var text = String(value).trim()
  var match = text.match(/(\d{4})-(\d{2})-(\d{2})\s+(\d{2}):(\d{2})(?::(\d{2}))?/)
  if (match) {
    return new Date(
      Number(match[1]), Number(match[2]) - 1, Number(match[3]),
      Number(match[4]), Number(match[5]), Number(match[6] || 0)
    ).toISOString()
  }
  var d = new Date(text)
  return isNaN(d.getTime()) ? new Date().toISOString() : d.toISOString()
}
```

要点:

- 完整时间会按本地时间构造 `Date`,再转 ISO。
- `昨天22:36`、`今天07:23`、`刚刚`、`30秒` 这类中文相对时间无法由 `new Date(text)` 正确解析,最终 fallback 到采集时间。
- `toConversationEvent` 又会再次调用 `_normalizeOccurredAt(rawMsg.timestamp || rawMsg.time || rawMsg.occurred_at)`,但传入的是上一步 ISO 时通常不再改变。

## 根因判断

当前最可能是采集侧时间解析和 DOM 时间策略组合导致:

1. **相对时间不支持**  
   `_normalizeOccurredAt` 不支持 `昨天/今天/刚刚/30秒`。解析失败会 fallback 到采集时间,造成部分消息 `occurred_at≈uploaded_at`。

2. **时间分隔继承策略不完整**  
   当前只在时间分隔文本是完整 `YYYY-MM-DD HH:mm` 时更新 `currentDate`。如果真实 DOM 分隔条是 `昨天22:46`、`今天07:23`、`刚刚`,就不会正确更新,后续消息可能 fallback 或继承旧值。

3. **消息级时间 XPath 过宽**  
   `_extractMessageTime` 使用 `.//span[contains(@class,"text-xs")]`,可能取到非时间 span。需要阶段二确认是否应改成 selector 快照里的更精确 `span.text-xs.text-gray-3.align-text-top.mr-2` 或在取到文本后做时间格式校验。

4. **raw_snapshot 信息不足**  
   当前 raw_snapshot 没存 `timeText/currentDate`,所以诊断无法精确区分某条消息是“独立时间误取”还是“继承时间误用”。阶段二修复时建议先加临时诊断字段或日志,但这属于采集改动,本阶段不做。

## 一、规范 v1(纳入 Chase 调整后定稿口径)

### 1.1 目录口径(固定,不再二选一)

| 位置 | 放什么 | 命名 |
|---|---|---|
| **仓库根**(五件套,不动) | `AGENTS.md` `CLAUDE.md` `PROJECT_STATUS.md` `CHANGELOG.md` `README.md` | 固定语义名,无日期无编号 |
| `docs/prd/` | 编码前设计:PRD、design、tasks、技术方案中"会指导实现"的部分 | `W##_design.md`(固定名+内部版本号+changelog,无日期无前缀) |
| `docs/research/` | 调研、盘点、现状核实 = **快照** | `YYYY-MM-DD_<W##或主题>_描述.md`(带日期) |
| `docs/reports/` | 验收、诊断、复盘结论 = **证据** | 带日期 或 `W##_acceptance/diagnosis` |
| `docs/ops/` | 流程与生产操作规程 | `release/prod-safety/versioning/server-access/engineering-governance` |
| `docs/meta/` **(新建)** | 文档治理、索引、技术债总纲、项目级长期说明 | 固定语义名,不放具体验收报告/一次性调研 |
| `docs/archive/` **(新建)** | 历史废弃文档(进 git,带取代关系说明) | 保留原名 |
| `docs/scratch/` | 临时草稿 | **不进 git** |

### 1.2 五条硬规则(Chase 拍板)

1. **根目录五件套不动**。`CHANGELOG.md` 被 `scripts/release-prod.sh` 写入,`PROJECT_STATUS.md` 被 `docs/ops/release.md`、`versioning.md`、`AGENTS.md` 引用——移动 = 改脚本/流程,不再是"只整理文档"。若要迁移另立 B 类治理任务。
2. **`CLAUDE.md` / `AGENTS.md` 必须留根**:CLAUDE.md 是 Claude Code 自动加载入口(本会话已确证注入),AGENTS.md 是 Codex 入口约定。工具依赖确凿 → 不动。
3. **`docs/meta/` 固定**,不再写"docs 根或 docs/meta"。docs 根下不再留散落 .md(现有散落文件正是混乱源)。
4. **两阶段,第一阶段不改正文**:Phase 1 只做盘点/分类/移动/改名/**改引用(链接路径)**;Phase 2 才给活文档补 changelog、给废弃文档加 superseded 标记。
5. **去重保守,不合并证据**:文档分 `canonical`(权威)/ `superseded`(被取代保留)/ `evidence`(历史证据,不合并不删)三态。仅"同主题+同结论+同时间窗+无新增证据"才可合并。多 agent 调研(cc/cc2/codex)= evidence,**全保留**。

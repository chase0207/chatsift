# W20.1 — 采集权只读接口

> 背景:W21 辅助采集器需在切换会话前判定"当前员工可否采该账号"。W20 heartbeat 只返回 account-block,不含采集权;
> 补一个轻量**只读**接口供 W21 消费(技术方案 §5 方案 A)。**只读、不改 W20 采集权写入逻辑。**

## 1. 接口契约
```
GET /api/v1/service-accounts/collect-permission
query: platform, platform_page, account_biz_id
200: { allowed:boolean, reason, lifecycle, collector_id, collector_kind }
reason ∈ ok | missing_account | pending_owner | not_collector | account_disabled | unknown
```

## 2. 语义(与 events batch 采集权闸门同口径,allowed iff batch 会接受)
| 情形 | allowed | reason |
|---|---|---|
| service_account 不存在 / 平台·页面映射不到 / 缺参 | false | missing_account |
| disabled | false | account_disabled |
| 本人 == collector_id(pending 或 active) | **true** | ok |
| pending 且非本人(已属临时采集人) | false | pending_owner |
| active 且非本人 | false | not_collector |
- ★**tenant_admin 不因管理员身份天然 allowed**,仍按 collector_id 判;**查看权 ≠ 采集权**。
- ★**只读**:不建账号、不 confirm、不分配、不改 lifecycle;首见建 pending 仍只走 events batch 路径。

## 3. 权限
- `router.use(auth)`:登录的**租户员工(external)**可调,**无 tenant_admin 管理权限要求**(不挂 `perm('service-account:*')`)。
- 查询恒带 `tenant_id = req.user.tenant_id` → 只查本租户账号(跨租户查不到 → missing_account)。
- **internal 平台方 → 403**(`平台方账号不可查询采集权`)。

## 4. 改动文件
- `server/src/controllers/v1/serviceAccountsController.js`(新):`collectPermission`。
- `server/src/routes/v1/serviceAccounts.js`(新):`GET /collect-permission`(auth)。
- `server/src/app.js`:挂载 `app.use('/api/v1/service-accounts', ...)`。

- **直连 controller 11/11 PASS**(`/tmp/w20_1_test.js`):采集人 pending/active=ok;非采集人 pending=pending_owner、active=not_collector;tenant_admin 非 collector=not_collector;disabled=account_disabled;missing_account(无账号/缺参)=missing_account;internal=403;返回字段齐全;**前后 service_accounts/audit 行数不变(零写库)**。
- **HTTP 冒烟**(临时端口 3101 连测试库):agent1(无 service-account:list perm)→ `{allowed:true,reason:"ok",lifecycle:"active",collector_id:3,collector_kind:"formal"}`;无 token → 401。


# W12.6 Acceptance — 消息时间/顺序修复

## DOM 结构确认

抖音私信消息时间是混合结构:

- A0(v1.2 新发现):每条消息容器内有隐藏的精确时间 `p.invisible.whitespace-nowrap.absolute`,文本形如 `2026-06-01 12:47:18`,精确到秒。
- A:消息节点可能有独立时间,历史选择器为 `span.text-xs.text-gray-3.align-text-top.mr-2`,示例 `2026-05-23 04:51:51`。
- B:消息流也有间隔分隔条,历史选择器为 `div.px-4.text-xs.text-center.text-gray-2.my-4`,示例 `2026-05-23 04:48`。

结论:v1.2 实现按 A0 精确隐藏时间优先;读不到 A0 时才走 v1.1 的相对时间/锚点兜底。

## 修复内容

`plugin/adapters/douyin/private-message.adapter.js`:

- 首选读取 `p.invisible.whitespace-nowrap.absolute`,并用 `YYYY-MM-DD HH:mm:ss` 正则二次确认,避免误抓其它隐藏节点。
- 采集开始固定 `collectAt`,所有相对时间以本轮采集时刻为基准。
- 支持解析:
  - `YYYY-MM-DD HH:mm[:ss]`
  - `MM-DD HH:mm`
  - `M月D日 HH:mm`
  - `今天/昨天 HH:mm`
  - `刚刚/刚才`
  - `N秒前/N分钟前/N小时前`
- 消息有隐藏精确时间时优先用隐藏精确时间。
- 读不到隐藏精确时间时,才使用旧独立时间/相对时间。
- 消息无独立时间时才继承最近的分隔条锚点。
- 分隔条解析失败会清空锚点,不会继续继承旧时间。
- 消息时间若小于等于上一条,按 DOM 顺序推进到上一条后一秒,保证入库顺序和 DOM 顺序一致。
- `raw_snapshot` 增加 `time_text/time_source/time_estimated`,后续可直接排查时间来源。

`plugin/content.js`:

- 重新由 `npm run build:plugin` 生成,同步上述 adapter 改动。

`admin/src/components/MessageDrawer.vue`:

- 聊天记录 drawer 打开并加载消息后自动滚到底部。

`admin/src/views/ConversationDetail.vue`:

- 会话详情消息流加载后自动滚到底部。

## 模拟采集验证

### v1.2 精确隐藏时间

用 Node VM 加载 `plugin/adapters/douyin/private-message.adapter.js`,模拟消息节点同时包含旧相对时间和隐藏精确时间:

```text
分隔条: 昨天 22:46
消息: 儿童节快乐
旧相对时间: 昨天 22:46
隐藏精确时间: 2026-06-01 12:47:18
```

输出:

```json
[
  {
    "content": "儿童节快乐",
    "timestamp": "2026-06-01T04:47:18.000Z",
    "source": "precise-invisible",
    "text": "2026-06-01 12:47:18"
  }
]
```

断言:隐藏精确时间优先于旧相对时间,`raw_snapshot.time_source=precise-invisible`。

### v1.1 兜底

用 Node VM 加载 `plugin/adapters/douyin/private-message.adapter.js`,模拟以下 DOM:

```text
分隔条: 今天 07:23
消息1: 早上好       无独立时间
消息2: 早上好2      无独立时间
消息3: 儿童节快乐   独立时间=昨天 22:46
消息4: 刚刚         无独立时间
```

输出:

```json
[
  { "content": "早上好", "source": "anchor" },
  { "content": "早上好2", "source": "anchor" },
  { "content": "儿童节快乐", "source": "relative-day+monotonic" },
  { "content": "刚刚", "source": "anchor+monotonic" }
]
```

断言:所有 `timestamp` 单调递增。`儿童节快乐` 不再把 DOM 顺序拉回上一天,而是按可见消息顺序保序。

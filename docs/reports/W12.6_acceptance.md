# W12.6 Acceptance — 消息时间/顺序修复

## DOM 结构确认

抖音私信消息时间是混合结构:

- A0(v1.3 确认):每条消息的隐藏精确时间 `p.invisible.whitespace-nowrap.absolute` 在消息列容器 `flex-1 flex flex-col` 内,是消息行 `flex items-center` 的前置兄弟,文本形如 `2026-06-01 14:26:36`,精确到秒。
- A:消息节点可能有独立时间,历史选择器为 `span.text-xs.text-gray-3.align-text-top.mr-2`,示例 `2026-05-23 04:51:51`。
- B:消息流也有间隔分隔条,历史选择器为 `div.px-4.text-xs.text-center.text-gray-2.my-4`,示例 `2026-05-23 04:48`。

结论:v1.3 实现从消息内容节点向上爬到 `flex-1 flex-col` 祖先容器,再读取 A0 精确隐藏时间;读不到 A0 时才走 v1.1 的相对时间/锚点兜底。

## 修复内容

`plugin/adapters/douyin/private-message.adapter.js`:

- 首选从消息内容节点向上爬到 `flex-1 flex-col` 祖先容器,在该容器内读取 `p.invisible.whitespace-nowrap.absolute`,并用 `YYYY-MM-DD HH:mm:ss` 正则二次确认,避免误抓其它隐藏节点。
- 采集开始固定 `collectAt`,所有相对时间以本轮采集时刻为基准。
- 支持解析:
  - `YYYY-MM-DD HH:mm[:ss]`
  - `MM-DD HH:mm`
  - `M月D日 HH:mm`
  - `今天/昨天 HH:mm`
  - `刚刚/刚才`
  - `N秒前/N分钟前/N小时前`
- 消息有隐藏精确时间时优先用隐藏精确时间。
- 读不到隐藏精确时间时,才使用旧独立时间/相对时间。
- 消息无独立时间时才继承最近的分隔条锚点。
- 分隔条解析失败会清空锚点,不会继续继承旧时间。
- 消息时间若小于等于上一条,按 DOM 顺序推进到上一条后一秒,保证入库顺序和 DOM 顺序一致。
- `raw_snapshot` 增加 `time_text/time_source/time_estimated`,后续可直接排查时间来源。

`plugin/content.js`:

- 重新由 `npm run build:plugin` 生成,同步上述 adapter 改动。

`admin/src/components/MessageDrawer.vue`:

- 聊天记录 drawer 打开时请求最新 100 条消息,服务端按倒序取数后再恢复正序返回,避免长会话只看到最旧消息。
- 聊天记录 drawer 加载消息后自动滚到底部。

`admin/src/views/ConversationDetail.vue`:

- 会话详情消息流同样请求最新 100 条消息并自动滚到底部。

`admin/src/views/Conversations.vue`:

- 会话中心搜索区增加“页面”下拉,选项取自平台管理中 `dom_status=3` 的生效页面,展示页面名称。
- 会话中心搜索区增加“昵称”和“消息”字段,保留查询/刷新/重置操作。
- 搜索区换行时增加行间距,避免两行控件贴在一起。
- 列表“平台页面”展示页面名称,找不到映射时回退原始 `platform_page`。

`server/src/controllers/v1/conversationsController.js`:

- 会话列表接口支持 `platform_page` 和 `nickname` 查询参数。
- 会话消息接口支持 `latest=1`,用于前端抽取最新 N 条消息再按时间正序展示。

### v1.3 精确隐藏时间

用 Node VM 加载 `plugin/adapters/douyin/private-message.adapter.js`,模拟用户确认的 DOM 层级:

```text
flex-1 flex flex-col
├─ p.invisible: 2026-06-01 14:26:36
└─ flex items-center
   └─ ... whitespace-pre-wrap: 谢谢你
```

输出:

```json
{
  "time_text": "2026-06-01 14:26:36",
  "time_source": "precise-invisible",
  "time_estimated": false
}
```

断言:时间 p 作为消息行兄弟节点时也能被读取,`raw_snapshot.time_source=precise-invisible`。

### v1.1 兜底

用 Node VM 加载 `plugin/adapters/douyin/private-message.adapter.js`,模拟以下 DOM:

```text
分隔条: 今天 07:23
消息1: 早上好       无独立时间
消息2: 早上好2      无独立时间
消息3: 儿童节快乐   独立时间=昨天 22:46
消息4: 刚刚         无独立时间
```

输出:

```json
[
  { "content": "早上好", "source": "anchor" },
  { "content": "早上好2", "source": "anchor" },
  { "content": "儿童节快乐", "source": "relative-day+monotonic" },
  { "content": "刚刚", "source": "anchor+monotonic" }
]
```

断言:所有 `timestamp` 单调递增。`儿童节快乐` 不再把 DOM 顺序拉回上一天,而是按可见消息顺序保序。

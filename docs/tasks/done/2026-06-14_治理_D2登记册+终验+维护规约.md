## 1. PM 指令

### 用大白话讲

这是最后一张,做完治理就"封箱",而且能拿出**证据**说没留漏洞。四件事:
1. **建规则登记册**:一张表,列出每条规则 → 它唯一的家 → 谁强制它(机器/人)。这是"有没有漏洞"唯一能一眼回答的地方。
2. **完整性终验**:照着登记册逐条确认——每条规则都有家、有强制者。发现"没家"或"没人强制又没人知道靠人"的,就地补或记下来。
3. **维护规约**:立一条死规矩——以后新增/改任何规则,必须在登记册登记并写明强制者,否则就是漏洞。这条专门堵"将来再留洞"。顺带补一句"根五件套(README 那批)位置不动 ≠ 内容不更新,新鲜度由 A1 守"(README 当初烂掉的根因)。
4. **正式收编 worktree + 同步账本**:把"治理/并行用独立 worktree、hook 每个 worktree 要生效"写进工程治理(你已实跑验证);把 project-workflow §4 账本全标 ✅。

### "无漏洞"判据(终验对照这个)

每条规则满足:① 只有一个家;② 有明确强制者(机器查 / 或登记在册的人工检查点)。
不满足的就是漏洞。**无漏洞 ≠ 全自动**——靠人判断的规则(如 A/B/C 分级)只要在册标"人",就算没掉下去。

### 文件边界
- **允许改 / 新增**:新增 `docs/ops/rules-index.md`(登记册);`docs/meta/document-governance.md`(加维护规约 + 五件套新鲜度那句);`docs/ops/engineering-governance.md`(加 worktree 规则);`docs/ops/project-workflow.md`(§4 账本标 ✅、相关 ⚠️ 缺口转已补)。新增终验报告到 `docs/reports/`。
- **禁止改**:业务代码、W23 PRD、各规则的**正文本身**(本单只登记/核对,不改规则内容)。

## 1. PM 指令

目标:
- 不继续 patch 现有共享目录。
- 直接重建 test/prod 发布隔离机制。
- 将“前端静态资源”和“插件下载产物”从环境和发布链路上拆开。
- 建立 test/prod 两套独立发布入口,后续业务版本必须基于该机制预发。

背景:
- 只读核实发现 prod 与 test 的 `server /app/public` 当前都挂载 `/opt/chatsift/admin/dist`。
- `admin/dist/plugin-downloads/metadata.json` 被 prod/test 共用。
- test 更新插件 metadata 会影响 prod 插件更新提示。
- PM-工程治理补充指出风险不止 plugin-downloads,还包括发布脚本、Nginx、DB/JWT、插件 serverUrl 与事件落点。
- 该问题表明现有 test/prod 发布模型不可信,不能只靠 Stop Gate 或人工提醒继续补丁式推进。

核心决策:
- v0.6.6 定义为“发布隔离机制重建”版本。
- 原 DOM 采集适配顺延为 v0.6.7。
- “抖音-消息-消息接待”顺延为 v0.6.8。

设计原则:
- test 不能读 prod 目录。
- test 不能写 prod 目录。
- test 插件 metadata 变化不能影响 prod。
- admin 静态资源发布与插件下载发布解耦。
- 发布脚本必须显式区分 test/prod,不能靠人记路径。
- 机制隔离优先于文档提醒。

## 2. 目标架构

### 2.1 目录模型

目标目录:

```text
prod:
  /opt/chatsift/
    admin/dist/              # prod 后台静态资源
    plugin-downloads/        # prod 插件 zip + metadata
    server/
    deploy/
    VERSION
    data/

test:
  /opt/chatsift-test/
    admin/dist/              # test 后台静态资源
    plugin-downloads/        # test 插件 zip + metadata
    server/
    deploy/
    VERSION
    data-test/
```

要求:
- `plugin-downloads` 不再放在 `admin/dist` 下面作为发版主路径。
- `admin/dist` 只承载后台前端静态资源。
- 插件下载目录独立,按环境配置。

### 2.2 server 插件下载目录

新增环境变量:

```text
PLUGIN_DOWNLOAD_DIR=/opt/chatsift/plugin-downloads
PLUGIN_DOWNLOAD_BASE_URL=/plugin-downloads
```

test:

```text
PLUGIN_DOWNLOAD_DIR=/opt/chatsift-test/plugin-downloads
PLUGIN_DOWNLOAD_BASE_URL=/plugin-downloads
```

server 行为:
- `/api/dashboard/plugin-update` 读取 `${PLUGIN_DOWNLOAD_DIR}/metadata.json`。
- `/api/dashboard/plugin-update/download` 读取 `${PLUGIN_DOWNLOAD_DIR}/${zipName}`。
- 不再依赖 `server/public/plugin-downloads` 或 `/app/public/plugin-downloads`。

### 2.3 静态资源目录

prod:

```text
chatsift-server /app/public <- /opt/chatsift/admin/dist
```

test:

```text
chatsift-server-test /app/public <- /opt/chatsift-test/admin/dist
```

### 2.4 发布入口

必须有明确的 test/prod 发布入口。二选一:

方案 A(推荐):新增统一脚本

```text
scripts/release.sh --env test --version 0.6.6
scripts/release.sh --env prod --version 0.6.6
```

方案 B:拆两个脚本

```text
scripts/release-test.sh 0.6.6
scripts/release-prod.sh 0.6.6
```

无论选择 A/B,必须做到:
- test 发布路径写死为 `/opt/chatsift-test/...`。
- prod 发布路径写死为 `/opt/chatsift/...`。
- test 脚本不得出现 `/opt/chatsift/admin/dist` 写入动作。
- prod 脚本不得读取 `.env.test` 或 test compose。
- 执行前打印计划,包含 env、目标 host、目标目录、compose 文件、metadata 路径、server 容器名。
- 执行前要求确认或 dry-run。

### 4.2 只读拓扑核实

- prod/test `metadata.json` 实际路径与版本。

### 4.3 改 server 插件下载路径

- `dashboard.js` 不再固定读 `public/plugin-downloads`。

- 若未配置,本地开发可 fallback 到 `server/public/plugin-downloads`,但 production/test compose 必须显式配置。

### 4.4 改 compose

prod:
- 保持 `/app/public <- /opt/chatsift/admin/dist`。
- 新增 `PLUGIN_DOWNLOAD_DIR=/opt/chatsift/plugin-downloads`。
- 如采用 volume mount,挂载 `/opt/chatsift/plugin-downloads` 到容器内同一路径或 `/app/plugin-downloads`。

test:
- `/app/public <- /opt/chatsift-test/admin/dist`。
- 新增 `PLUGIN_DOWNLOAD_DIR=/opt/chatsift-test/plugin-downloads`。
- 不得引用 `/opt/chatsift/admin/dist`。

### 4.5 改打包与发布脚本

最低要求:
- `package-plugin.sh` 支持输出目录参数,例如:
  ```text
  bash scripts/package-plugin.sh --out /tmp/chatsift-plugin-build/plugin-downloads "notes"
  ```
- 默认行为兼容当前本地用法。
- test/prod 发布脚本负责将输出目录 rsync 到各自环境的 `plugin-downloads`。

推荐要求:
- 新增 `scripts/release.sh --env test|prod`。
- 支持 `--dry-run`。
- test/prod 环境参数集中定义:
  - remote dir
  - admin dist dir
  - plugin dir
  - compose file
  - env file
  - server container
  - port
- 脚本内置 guard:
  - `--env test` 时,目标路径中不得出现 `/opt/chatsift/admin/dist`。
  - `--env prod` 时,不得引用 `/opt/chatsift-test`。

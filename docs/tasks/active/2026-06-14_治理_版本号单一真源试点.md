## 1. PM 指令

### 目标（用大白话）

把"当前是哪个版本"这件事，从**散落在多个文档里、且已经各说各的**，收拢成**只有一个地方说了算**，再写一个**小脚本替人去查**有没有人又写乱。这是一次"试点"——只拿"版本号"这一条规则练手，跑通后同样的做法再推广到别的规则。

对应三个目标：
- **规范化** = 版本号只有一个家（PROJECT_STATUS.md），别处只引用、不写死。
- **自动化** = 一个只读脚本，自动报出"谁又把版本号写死了""哪个文档头和它的变更日志对不上"。
- **稳定性** = 从此不靠人记得去擦，机器替人查。

### 为什么是版本号

因为它现在漂得最明显，四个地方四个数：README 说还停在 W0–W10；release.md 说"当前 W16=v0.3.1 / W17=v0.4.0"；server-access 说"prod VERSION=0.5.0"；而实际 prod 已是 v0.6.7。正好用它演示三步长什么样。

### 问题定性

- **Problem Layer**：文档治理 + 轻量 tooling（非业务代码、非数据契约、非生产操作）。
- **Long-term Correct Direction**：每条规则只有一个家（SSOT），且由"机制/脚本"而非"人工记忆"强制。版本号是第一个试点，跑通后同法逐条推广到其余规则。
- **Current Phase Closure**：本任务只闭环"版本号"这一条规则的规范化 + 一个只读检查脚本。**不**接入 pre-commit、**不**动其他规则、**不**做 README 的其余过期内容。
- **Deferred Items + Trigger**：见 §8。

### 范围（只做这些）

把三处写死的"当前版本"声明，改成一句指向 PROJECT_STATUS 的话；新增一个只读检查脚本；写一行用法说明。

### 不做

- 不动 versioning.md / CHANGELOG.md 里的**历史版本表**（那是版本记录/历史映射，本就该有版本号，是真源不是漂移）。
- 不动 server/admin/plugin 任何业务代码。
- 不把脚本接入 pre-commit / CI（等它手动跑稳了再说，见 Deferred）。
- 不顺手修 README 的其他过期内容（Node 版本、目录结构等，见 Deferred）。

### 文件边界

- **允许改**：
  - `PROJECT_STATUS.md`（确认/补一行"当前版本"唯一真源）
  - `README.md`（仅"开发阶段"那张表）
  - `docs/ops/release.md`（仅 §1 的"当前 = …"那一行）
  - `docs/ops/server-access.md`（仅 §6.3 写死的 `0.5.0`；外加一行脚本用法）
  - 新增 `scripts/check-doc-freshness.sh` 或 `.js`
- **禁止改**：上面"允许改"之外的一切，尤其 `versioning.md` 历史表、`CHANGELOG.md`、业务代码。

### 上位规则

- 本任务单不覆盖 `AGENTS.md`、`PROJECT_STATUS.md`、`docs/ops/prod-safety.md`。如有冲突，停下回报。

## 2. 执行步骤

1. **确认/建立单一真源。**
   读取真实当前版本（以仓库 `VERSION` 文件 + 最新 git tag 为准，不要凭记忆）。
   打开 `PROJECT_STATUS.md`，确认其中是否有一处明确写明"当前版本 / 当前 prod 版本"。
   - 有 → 记下确切措辞与位置，作为唯一真源。
   - 没有 → 在 `PROJECT_STATUS.md` 补一行清晰的"当前版本：vX.Y.Z（来源：VERSION 文件 / 最新 tag）"，作为唯一真源。

2. **规范化（改三处，只改"当前版本"声明，周边真规则不动）。**
   - `README.md` 的"开发阶段"表（整张表停在 W0–W10，已过期）→ 整张表替换为一句："当前版本与开发进度见根目录 `PROJECT_STATUS.md`。"
   - `docs/ops/release.md` §1 里"当前：W16 = v0.3.1；W17 = v0.4.0"这一行 → 替换为："当前版本以 `PROJECT_STATUS.md` 为准。"**保留**同节其余规则（W 大功能→minor、补丁→patch 等）。
   - `docs/ops/server-access.md` §6.3 里写死的 `prod VERSION=0.5.0（…）` → 把版本号替换为："当前 prod 版本见 `PROJECT_STATUS.md`。"**保留**"发版范围由 Chase/QA 定，cc 不自决"这句规则。

3. **自动化（新增只读检查脚本，不引入任何新依赖）。**
   新增 `scripts/check-doc-freshness.sh`（或 `.js`，用仓库现有运行时即可）。脚本做两件事并打印结果，**只读、绝不自动改文件**：
   - **检查 A（单一真源）**：扫描 `README.md`、`docs/ops/release.md`、`docs/ops/server-access.md`，若在"当前 / 开发阶段 / prod VERSION"等**状态语境**里发现写死的产品版本号（形如 `v0.x.y` 或 `VERSION=0.x.y`），报 `WARN` 并列出文件 + 行。（`CHANGELOG.md`、`versioning.md` 的历史表不在扫描范围。）
   - **检查 B（文档头一致）**：对每个带 changelog 表的治理文档（AGENTS、各 docs/ops、各 docs/meta），核对文件头 `版本：` 是否等于其 changelog 表顶行的版本号；不一致报 `WARN` 并列出文件。
   - **输出**：逐条 `[PASS]/[WARN] 文件 说明`，末尾汇总 `PASS x / WARN y`。

4. **自测（证明"摄像头"真的会抓——这步是本任务的重点）。**
   - 先跑一次，应**全 PASS**（因为第 2 步刚改完）。把输出贴回 §5。
   - 故意在 `README.md` 写回一个假的"当前 v0.5.0"，再跑，确认脚本 `WARN` 抓到。
   - 把假版本号改回，再跑，确认恢复全 PASS。
   - 三次输出都贴回 §5。

5. **用法说明。** 在 `docs/ops/server-access.md`（或 release.md）加一行，写明脚本怎么跑（例：`bash scripts/check-doc-freshness.sh`）。

6. **收尾。** `git status` 干净；改动作为独立 `docs:`/`chore:` commit；回写 §5、§6，Status 改为 `ready_for_review`，Next Owner = Review（codex）。

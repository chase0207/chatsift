# M3:理清 git + push(W17 前置)

> **为什么现在做**:本地领先 origin ~11 commit、含 v0.2.9~v0.3.1 多个发版 tag 全未推;多 agent 同分支并行导致 commit 交错(codex/cc 的 commit 混在一起)。W17 是大改动(动采集核心+数据契约),必须在干净的 git 状态上做,否则叠加后更乱、回滚危险。
> **目标**:把现有工作安全 push 到 origin、理清交错分支、main 干净可作为 W17 的起点。
> **★最高原则:单 agent 全程做 M3,期间其他 agent 不碰这个仓库(避免边理边乱)。**
> **★这是 git 历史操作,有风险,先看清现状再动手,每一步可逆优先。**

---

## 0. 前置:指定单一 agent + 隔离

- **指定一个 agent 全程执行 M3**(Chase 指定)。
- 执行期间,**其他 agent 暂停对本仓库的任何写操作**(不 commit、不切分支、不 push)。
- 避免"一边理一边有新 commit 进来"导致越理越乱。

---

## 1. 先看清现状(只看不动)

```bash
cd ~/vscode/chatsift
git status                          # 当前在哪个分支、工作区干不干净
git branch -a                       # 所有本地+远程分支
git log --oneline --graph --all -30 # 看分支拓扑、commit 交错情况
git log origin/main..HEAD --oneline 2>/dev/null || echo "无upstream"  # 本地领先origin多少
git tag                             # 本地有哪些 tag
git ls-remote --tags origin 2>/dev/null # 远程有哪些 tag(对比哪些没推)
```

回报现状:
- 当前分支、工作区是否干净(有没有未提交/未跟踪文件)
- 有哪些分支,哪个是 main,哪些是并行工作分支(w16-platform-tenant-split 等)
- 本地领先 origin/main 多少 commit、哪些 commit 是哪个 agent 的(尽量标注)
- 哪些 tag 本地有、远程没有(待推)
- commit 交错的具体情况(codex/cc 的混在哪)

**看完现状先停,把现状报 Chase,确认理清策略后再动手。** 不要看完直接 push。

---

## 2. 理清策略(看完现状后,和 Chase 确认再执行)

> 具体怎么理取决于现状。下面是常见情况的处理原则,实际按 §1 看到的拓扑定。

### 2.1 未跟踪/未提交文件归位
- 工作区的未跟踪文件(如 tools/、tech-debt-inventory-*.md、各种报告)先归位:
  - 该提交的(文档、工具)→ 分类 commit(docs: / chore:)
  - 不该进库的(临时文件)→ gitignore 或删除
- 目标:工作区干净(git status clean)

### 2.2 分支处理
- 确认哪个分支是"真相"(含最新正确代码):大概率是 w16 分支(W16 在那做的)还是 main?
- 如果工作成果在 w16 分支、main 落后 → 把 w16 合回 main(注意:可能有 cherry-pick 双份,git 一般按 patch-id 去重,但要核对合并结果无重复/无丢失)
- 合并后确认 main 包含所有正确的工作成果(W14/W16/文档等)

### 2.3 push
- main 理清、确认正确后:`git push origin main`
- tags:`git push origin --tags`(推 v0.2.9~v0.3.1 等本地发版 tag)
- push 前最后确认:main 上的代码 == 当前生产实际运行的代码(避免推上去的和线上不一致)

---

## 3. 安全护栏(git 历史操作)

- **禁止 force push main**(OPS §1.1:会破坏 release tag 历史)。如果遇到"必须 force 才能推"的情况,停下报 Chase,大概率是哪里理错了。
- **合并/rebase 前先备份当前状态**:`git branch backup-before-m3-$(date +%Y%m%d)` 留一个备份分支,万一理乱了能回到这个点。
- **可逆优先**:优先用 merge(可逆)而非 rebase(改写历史);优先新建分支而非删分支。
- **每个破坏性 git 操作前**(reset --hard / branch -D / force / rebase)→ 停,确认这一步删的/改的是什么、能不能回退。
- 不确定就停下报 Chase,不猜着操作。

---

## 4. 验收

```
- git status 工作区干净(无未提交/未跟踪)
- main 包含所有正确工作成果(W14/W16/文档),无丢失
- 本地 commit + tags 已 push 到 origin(git log origin/main..HEAD 为空)
- 远程 tags 与本地一致
- 分支拓扑清晰(并行交错的已合并/归位)
- main 代码 == 生产实际运行代码(一致)
- 备份分支 backup-before-m3-* 保留(以防万一,确认稳定后再删)
```

回报:理清前后的分支拓扑对比、push 了哪些 commit/tag、main 现在的状态。

---

## 5. 完成后

- M3 完成 = main 干净、已 push、可作为 W17 的起点。
- **W17 从理清后的 main 切一个干净的 W17 分支**(如 `w17-message-position`),指定单一 agent 在该分支做,不再多 agent 同分支并行。
